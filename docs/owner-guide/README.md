# Документация панели магазина для владелицы и сотрудников

Здесь лежит инструкция к панели магазина: где что находится и как сделать частые дела. Её читают
владелица магазина и сотрудницы. У каждого шага есть снимок экрана. Снимки делает скрипт со стенда,
и проверка находит снимки, которые устарели после изменения панели.

Читают её в самой панели: пункт «Справка» внизу меню открывает в новой вкладке `/help/` на том же
адресе, что и панель (panel.cherkashino.ru/help/ и панель INTL). Для отправки магазину файлом есть
один HTML-файл.

| Файл | Что в нём |
|---|---|
| [guide/](guide/) | страницы инструкции по-русски, по одной на раздел; кадры подключены как `![…](shots/<id>.webp)` |
| [guide/shots/](guide/shots/) | кадры, WebP без потерь; лежат в git, см. ниже |
| [scenes.mjs](scenes.mjs) | список кадров: роль, адрес экрана, что нажать, что обвести, из какого кода экран нарисован |
| [shoot.mjs](shoot.mjs) | снимает кадры со стенда в `guide/shots/` и пишет `shots.lock.json` |
| [shots.lock.json](shots.lock.json) | с чего снят каждый кадр: хеш кода экрана, хеш его текстов, хеш самого кадра, коммит; и текст, который кадр показывает |
| [check.mjs](check.mjs) | проверка: какие кадры устарели и почему, все ли файлы кадров на месте |
| [publish.mjs](publish.mjs) | собирает справку с навигацией (`--site`) и один HTML-файл для отправки (`--html`) |

## Где живёт документация и почему

Текст, список кадров, кадры и инструменты лежат здесь, в репозитории, рядом с кодом панели. Проверка
свежести сравнивает кадры с кодом того же коммита, поэтому они должны жить вместе.

**Кадры в git.** Справка выкладывается вместе с панелью: образ панели собирает её из этой папки, и
кадры должны быть в том же коммите, что и страницы. Ещё GitHub показывает страницы `guide/` сразу с
картинками. Чтобы история не росла быстро, кадры хранятся в WebP без потерь: те же точки, что в PNG,
а весь набор из 42 кадров весит около 2,3 МБ. Пересъёмка меняет только кадры устаревших экранов.

**На кадрах только условные данные.** Кадры видит любой, кто открыл справку, поэтому настоящих людей на
них нет. Логины стенда условные: «Владелица Пример» owner@example.ru, «Менеджер Анна»
manager1@example.ru, «Менеджер Мария» manager2@example.ru, «Оператор Пример» operator@example.ru.
Покупатели обезличены, реквизиты продавца заглушечные, склад называется «Склад магазина». Название
магазина «Черкашино» остаётся: это не имя человека. Две проверки держат это правило:

1. `shoot.mjs` перед снимком читает текст экрана и значения полей. Если там фамилия человека магазина
   или рабочая почта, кадр не снимается, и скрипт называет его. Фамилии записаны в
   [lib.mjs](lib.mjs) хешами, чтобы самих имён в репозитории не было.
2. Текст каждого кадра записывается в `shots.lock.json`, и тест панели
   (`apps/tenant-panel/src/__tests__/owner-guide.test.mjs`) ищет те же слова там. `check.mjs` следит,
   что файл кадра в git тот самый, что снял `shoot.mjs`: хеш файла совпадает с записанным.

**Справка собирается при сборке образа панели.** [Dockerfile](../../apps/tenant-panel/Dockerfile)
панели копирует эту папку и после `vite build` запускает `publish.mjs --site dist/help`; nginx отдаёт
`/help/` как обычные файлы. Готовой сборки в git нет: она повторяла бы страницы и кадры, и её
пришлось бы пересобирать руками после каждой правки текста, а забытая пересборка выложила бы старую
справку. `publish.mjs` работает на одном Node без пакетов и останавливает сборку образа, если
страница показывает кадр, которого нет.

## Как устроена справка

`publish.mjs --site <папка>` собирает `index.html` (оглавление и таблица «Частые дела») и по странице
на раздел: `<папка>/02-zakazy/index.html` и так далее. Ссылки относительные, поэтому сборку можно
открыть с любого статического сервера.

- Компьютер, от 1024 px: слева закреплённое меню разделов; у открытого раздела под ним его
  подзаголовки, сам раздел подсвечен. Текст шириной не больше 760 px.
- Телефон, до 1024 px: сверху полоса с названием и кнопкой «Разделы», она открывает список разделов на
  весь экран.
- Внизу каждой страницы «← Предыдущий» и «Следующий →».
- Картинки грузятся лениво. Нажатие на картинку показывает её целиком, Esc или ещё одно нажатие
  закрывает. Без скрипта картинка открывается отдельной страницей, а «Разделы» всё равно работают.
- `noindex`, системный шрифт, светлая тема. Чужих адресов страница не запрашивает: ни шрифтов, ни
  скриптов.

`publish.mjs --html <файл>` собирает всё в один файл с кадрами внутри: оглавление со всеми
подзаголовками сверху, у каждого раздела ссылка «↑ К оглавлению».

```bash
node docs/owner-guide/publish.mjs --site /tmp/help/help --html /tmp/panel-help.html
python3 -m http.server 5191 --directory /tmp/help   # справка на http://127.0.0.1:5191/help/
```

## Снять кадры

Нужен стенд: бэкенд на обезличенной копии базы
([apps/backend/src/scripts/tenant-only](../../apps/backend/src/scripts/tenant-only/README.md), `--anonymize --verify`)
и панель (`apps/tenant-panel`, `vite`). С живой панели не снимать: на ней настоящие покупатели.
Обезличивание копии не трогает логины магазина и тексты, которые магазин написал сам: страницы,
курсы, уроки. Логины на стенде заводятся заново с условными именами (список выше), а имена людей в
текстах заменяются; `shoot.mjs` назовёт кадр, где что-то осталось.

Ещё нужен `cwebp` (`brew install webp`): кадры сохраняются в WebP без потерь.

На стенде нужны три логина магазина (владелец, менеджер, оператор) и файл с id записей, которые
показывают кадры:

```jsonc
{
  "product": "prod_…",          // товар с фотографиями
  "course": "crs_…",            // курс с уроками
  "lesson": "lsn_…",            // урок этого курса
  "orderPack": "order_…",       // оплаченный заказ с доставкой, ещё не собран
  "orderPacked": "order_…",     // собранный заказ, ещё не передан в доставку
  "orderShipped": "order_…",    // заказ в доставке
  "orderPaymentWait": "order_…",// заказ, оплату которого нужно подтвердить
  "orderCourse": "order_…"      // заказ курса, ждёт оплату
}
```

```bash
node docs/owner-guide/shoot.mjs --base http://localhost:5181 \
  --logins <файл с логинами стенда> --ids <файл с id>
```

Кадры ложатся в `guide/shots/`, `shots.lock.json` обновляется. Один Chromium, по вкладке на роль, окно
1440×900, светлая тема, русский язык. Видео и trace не пишутся. Запросы к любому адресу, кроме стенда,
обрываются, и скрипт печатает, сколько их было. `--only 02-orders,02-order-pack` переснимает только
эти кадры. Перед коммитом посмотрите новые кадры глазами.

## Проверка свежести

```bash
node docs/owner-guide/check.mjs
```

Кадр считается устаревшим, если после съёмки изменилось одно из двух:

1. **Код экрана.** Файлы из `sources` сцены плюс меню панели. Проверка называет изменённые файлы
   (`git diff` от коммита съёмки).
2. **Тексты экрана.** Строки `ru.json` с префиксами из `i18n` сцены и строки меню. Проверка называет
   изменённые ключи.

Ещё проверка падает, если страница показывает кадр, которого нет в `scenes.mjs` или в `guide/shots/`,
если сцену не показывает ни одна страница, если в `guide/shots/` лежит кадр, который никто не
показывает, если файл кадра не совпадает с `shots.lock.json` и если папки из `sources` больше нет.

Хеши не видят того, что меняется вне этих файлов: общие стили, обновление зависимостей, данные стенда.
Для этого есть сравнение по кадрам. Снимите кадры заново в отдельную папку, не трогая lock, и сравните
с кадрами в git:

```bash
node docs/owner-guide/shoot.mjs … --out /tmp/guide-now --no-lock --compare docs/owner-guide/guide/shots
```

Скрипт назовёт каждый кадр, где изменилось больше 0,5 % точек. Побайтно кадры не сравниваются: два
снимка одного и того же экрана расходятся в нескольких сглаженных точках. Даты «около 6 часов назад»
на экранах заказов меняются со временем, поэтому такой кадр нужно посмотреть глазами.

В `pr-checks.yml` проверка идёт шагом «Owner guide» с `--warn`: она печатает устаревшие кадры в
журнал проверки запроса, но не блокирует его. Обновить кадры может только тот, у кого есть стенд.
Тест панели при этом запускает `check.mjs --structure`, которому стенд не нужен: пропавший файл кадра
сломал бы сборку образа, поэтому он ловится уже в запросе.

## Когда панель изменилась

1. `node docs/owner-guide/check.mjs` — список устаревших кадров.
2. Переснять их: `shoot.mjs … --only <id,id>`. Кадры в `guide/shots/` и `shots.lock.json` обновятся.
3. Посмотреть новые кадры и поправить текст на странице `guide/`, если шаги стали другими.
4. Новый экран — новая сцена в `scenes.mjs` и ссылка на кадр на странице.
5. Посмотреть справку: `node docs/owner-guide/publish.mjs --site <папка>/help` и статический сервер.
   Кадры и страницы коммитятся вместе; в панель справка попадёт со следующей сборкой образа.
