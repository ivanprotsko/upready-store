# Документация панели магазина для владелицы и сотрудников

Здесь лежит инструкция к панели магазина: где что находится и как сделать частые дела. Её читают
владелица магазина и сотрудницы. У каждого шага есть снимок экрана. Снимки делает скрипт со стенда,
и проверка находит снимки, которые устарели после изменения панели.

| Файл | Что в нём |
|---|---|
| [guide/](guide/) | страницы инструкции по-русски, по одной на раздел; кадры подключены как `![…](shots/<id>.png)` |
| [scenes.mjs](scenes.mjs) | список кадров: роль, адрес экрана, что нажать, что обвести, из какого кода экран нарисован |
| [shoot.mjs](shoot.mjs) | снимает кадры со стенда и пишет `shots.lock.json` |
| [shots.lock.json](shots.lock.json) | с чего снят каждый кадр: хеш кода экрана, хеш его текстов, хеш самого кадра, коммит |
| [check.mjs](check.mjs) | проверка свежести: какие кадры устарели и почему |
| [publish.mjs](publish.mjs) | собирает страницы с кадрами в папку и в один HTML-файл, который можно отправить магазину |

## Где живёт документация и почему

Текст, список кадров и инструменты лежат здесь, в репозитории, рядом с кодом панели. Проверка
свежести сравнивает кадры с кодом того же коммита, поэтому они должны жить вместе.

Картинок в git нет. Снимки панели меняются при каждой правке интерфейса, и бинарные файлы в истории
только растут. Кроме того, снимки со стендов в репозиторий не кладут. Кадры снимаются в папку вне
репозитория, а читают готовую сборку `publish.mjs`: папку со страницами и картинками или один HTML-файл.

## Снять кадры

Нужен стенд: бэкенд на обезличенной копии базы
([apps/backend/src/scripts/tenant-only](../../apps/backend/src/scripts/tenant-only/README.md), `--anonymize --verify`)
и панель (`apps/tenant-panel`, `vite`). С живой панели не снимать: на ней настоящие покупатели.

На стенде нужны три логина магазина (владелец, менеджер, оператор) и файл с id записей, которые
показывают кадры:

```jsonc
{
  "product": "prod_…",          // товар с фотографиями
  "course": "crs_…",            // курс с уроками
  "lesson": "lsn_…",            // урок этого курса
  "orderPack": "order_…",       // оплаченный заказ с доставкой, ещё не собран
  "orderPacked": "order_…",     // собранный заказ, ещё не передан в доставку
  "orderShipped": "order_…",    // заказ в доставке
  "orderPaymentWait": "order_…",// заказ, оплату которого нужно подтвердить
  "orderCourse": "order_…"      // заказ курса, ждёт оплату
}
```

```bash
node docs/owner-guide/shoot.mjs --base http://localhost:5181 \
  --logins <файл с логинами стенда> --ids <файл с id> --out <папка вне репозитория>
```

Один Chromium, по вкладке на роль, окно 1440×900, светлая тема, русский язык. Видео и trace не пишутся.
Запросы к любому адресу, кроме стенда, обрываются, и скрипт печатает, сколько их было.
`--only 02-orders,02-order-pack` переснимает только эти кадры.

## Проверка свежести

```bash
node docs/owner-guide/check.mjs
```

Кадр считается устаревшим, если после съёмки изменилось одно из двух:

1. **Код экрана.** Файлы из `sources` сцены плюс меню панели. Проверка называет изменённые файлы
   (`git diff` от коммита съёмки).
2. **Тексты экрана.** Строки `ru.json` с префиксами из `i18n` сцены и строки меню. Проверка называет
   изменённые ключи.

Ещё проверка падает, если страница показывает кадр, которого нет в `scenes.mjs`, если сцену не
показывает ни одна страница и если папки из `sources` больше нет.

Хеши не видят того, что меняется вне этих файлов: общие стили, обновление зависимостей, данные стенда.
Для этого есть сравнение по кадрам. Снимите кадры заново в отдельную папку, не трогая lock, и сравните
с теми, с которыми документ опубликован:

```bash
node docs/owner-guide/shoot.mjs … --out /tmp/guide-now --no-lock --compare <папка опубликованных кадров>
```

Скрипт назовёт каждый кадр, где изменилось больше 0,5 % точек. Побайтно кадры не сравниваются: два
снимка одного и того же экрана расходятся в нескольких сглаженных точках. Даты «около 6 часов назад»
на экранах заказов меняются со временем, поэтому такой кадр нужно посмотреть глазами.

В `pr-checks.yml` проверка идёт шагом «Owner guide» с `--warn`: она печатает устаревшие кадры в
журнал проверки запроса, но не блокирует его. Обновить кадры может только тот, у кого есть стенд.

## Когда панель изменилась

1. `node docs/owner-guide/check.mjs` — список устаревших кадров.
2. Переснять их: `shoot.mjs … --only <id,id>`. `shots.lock.json` обновится.
3. Посмотреть новые кадры и поправить текст на странице `guide/`, если шаги стали другими.
4. Новый экран — новая сцена в `scenes.mjs` и ссылка на кадр на странице.
5. Собрать: `node docs/owner-guide/publish.mjs --shots <папка кадров> --out <папка> --html <файл.html>`.
