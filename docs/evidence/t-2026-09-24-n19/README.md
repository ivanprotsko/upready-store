# t-2026-09-24-n19 — шаг оплаты называл город и индекс, когда не хватало другого поля: доказательства

Замеры сняты 30.09 примерно с 13:45 до 13:58 WITA на стенде: бэкенд 9611 (`medusa develop`, БД `upready_store_ex_11`, копия `upready_store_live_copy`), витрина 8611 (только `next build && next start`, с env МТ-деплоя). Магазин olavka на хосте `olavka-com.localhost`, доставка курьером (DHL Express), товар «Стевия в таблетках». Имя, телефон и почта покупателя в сценариях выдуманы. Из данных покупателей копии ничего не читалось. После замера стенд погашен.

## Воспроизведение

`repro-payment-step.mjs`: четыре корзины на 1440 и 390. Итоги лежат в `repro-before.json` (dev 4bcc7302) и `repro-after.json` (эта ветка). Снимки — `shots/<before|after>-<корзина>-<ширина>.webp`, на всю страницу.

| Корзина | Чего нет в адресе корзины | До: красная фраза | После: красная фраза |
|---|---|---|---|
| `form-full`: форма заполнена целиком | — | нет | нет |
| `form-no-street`: в форме пустая улица, индекс, город и область заполнены, нажато «Сохранить» | лист адреса: улицы | «Заполните обязательные поля адреса. Без города и почтового индекса заказ не отправить.» | «Заполните обязательные поля адреса: Адрес.» |
| `api-no-province` (путь 24.09): адрес через store API — улица, город, индекс, без области | province | над «Оплатить»: «…Без города и почтового индекса заказ не отправить.» | «Выберите область из списка.» |
| `api-no-street`: через store API — область, город, индекс, без улицы | address_1 | над «Оплатить»: «…Без города и почтового индекса заказ не отправить.» | «Заполните обязательные поля адреса: Адрес.» |

«Оплатить» серая во всех четырёх корзинах. В трёх неполных она серая и должна быть: адрес не принял бы и бэкенд. В `form-full` не заполнена демокарта. Цвет фразы «после» замерен: `rgb(244, 63, 94)` (`text-rose-500`), на обеих ширинах.

## Причина

Проверка верна: `shippingAddressGaps` требует те же поля, что бэкенд-гейт `missingPostableFields` в `apps/backend/src/workflows/hooks/validate-cart-shipping-address.ts`: `address_1`, `postal_code`, `city`, а для `ru` ещё `province`. Ошибка была в тексте, в двух местах.
1. Шаг оплаты (`checkout-payment-section`) показывал `addressIncomplete` при любом пробеле, в том числе при пустой области. Разделение из U-08 (#189) туда не дошло.
2. Сам `addressIncomplete` был неизменным текстом про город и индекс. Лист адреса выводил его и тогда, когда не хватало только улицы.
