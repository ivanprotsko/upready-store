# docs/evidence — правило для снимков со стендов

Здесь лежат доказательства к задачам: замеры, логи, снимки экрана. Стенд, восстановленный из копии
боевой базы, показывает настоящих покупателей: имена под отзывами, адреса, телефоны, номера заказов.
Снимок, попавший в git, есть на GitHub, во всех клонах и рабочих пространствах, и убрать его оттуда
можно только переписав историю.

## Правило

1. Снимки и записи экрана для `docs/evidence` снимают только со стенда на обезличенной базе. Это копия,
   прогнанная через `--anonymize` и прошедшая `--verify`
   ([apps/backend/src/scripts/tenant-only](../../apps/backend/src/scripts/tenant-only/README.md)), или
   свежая база из посева, где настоящих людей нет.
2. Каждый новый или изменённый файл png, jpg, jpeg, webp, gif, avif, bmp, tif, tiff, heic, mp4, webm, mov
   лежит в папке задачи `docs/evidence/<задача>/` и записан в её `EVIDENCE.yml`. В записи указаны источник
   и sha256 файла.
3. Снимок, который уже лежит в git и показывает данные, закрашивают на месте непрозрачным
   прямоугольником, не меняя имени и размера. В записи тогда остаётся настоящий источник и добавляется
   `redacted:`: задача и что закрашено. Новый файл так не добавить.

## Формат `EVIDENCE.yml`

```yaml
# Откуда снимки этой папки. Правило и формат: docs/evidence/README.md.
shots/after-home-1440.webp:
  source: обезличенная база upready_store_anon_14
  sha256: 3f1c…
```

Ключ записи — путь файла от папки задачи с двоеточием на конце. Под ним строки `  ключ: значение`,
ровно с двумя пробелами в начале. Допустимые ключи: `source` и `sha256` (обязательны) и `redacted`.
Новый файл принимается только с `source: обезличенная база <имя>`. В значении не бывает `: ` и ` #`.
Хеш считается так: `shasum -a 256 <файл>`.

## Проверка

`pnpm check:evidence` запускает [scripts/check-evidence-manifest.mjs](../../scripts/check-evidence-manifest.mjs).
Она сравнивает рабочее дерево с `origin/dev` (другую базу задают `--base <ref>` или `EVIDENCE_BASE`) и падает,
если новый или изменённый файл не записан в манифест, если новый файл не из обезличенной базы, если запись
называет несуществующий файл или sha256 не совпадает. В CI это шаг «Evidence screenshots» задания
«Panel And Repository» в [pr-checks.yml](../../.github/workflows/pr-checks.yml).

Файлы, которые лежали здесь до правила и с тех пор не менялись, проверка не трогает. В t-2026-10-03-59
просмотрены все 109 таких снимков: данные были на восьми, их закрасили, они записаны в
[t-2026-09-27-06/EVIDENCE.yml](t-2026-09-27-06/EVIDENCE.yml).
