## 0. Развилка, которую нужно решить ДО инструкции

Яндекс ID — единственный из пяти сервисов, где вопрос не «как быстрее провести клиента», а **чьё приложение**:

**Вариант А. Одно приложение upready на все витрины.** Redirect URI добавляем по домену каждого тенанта —
это разрешено: «добавьте дополнительные Redirect URI» (YA7). Верификацию через Госуслуги проходим **один раз мы**
и получаем поддержку разработчиков и снятие лимита приложений (YA8, YA4).
*Цена:* на экране согласия покупатель видит наш сервис, а не магазин клиента; при уходе клиента вход придётся переносить.

**Вариант Б. Приложение на каждого клиента.** На экране согласия — имя магазина.
*Цена:* верификацию каждого аккаунта может пройти **только** владелец бизнеса лично: «Войдите в профиль Госуслуг от имени
генерального директора или другого единоличного исполнительного органа организации» (YA2), и «Подтвердить другим способом
не получится» (YA3). Без верификации на аккаунт приходится не больше пяти приложений (YA4).

Решение за Иваном; техническая часть у нас одинаковая в обоих вариантах.

## 1. Пошаговая инструкция (вариант Б — приложение клиента)

| № | Шаг | Кто делает | Почему так |
|---|---|---|---|
| 1 | Вход в oauth.yandex.ru под аккаунтом, от имени которого создаётся сервис | **только клиент** | приложение навсегда принадлежит этому аккаунту |
| 2 | Создание приложения: тип «Для авторизации пользователей», права `login:email` и `login:info` | **можем сделать мы** (по экрану вместе с клиентом) | «разработчик должен зарегистрировать приложение в сервисе» Яндекс OAuth (YA5) |
| 3 | Redirect URI по всем доменам магазина (основной, www, кириллический в punycode, локальный стенд) | **можем сделать мы** | несколько Redirect URI в одном приложении разрешены (YA7). Кириллический домен Яндекс принимает только в punycode — конвертировать кодеком, не на глаз |
| 4 | Верификация сервиса через Госуслуги | **только клиент** | «подтвердите личность через Госуслуги» (YA1); для организации — лично гендиректор (YA2, YA3) |
| 5 | CLIENT_ID и CLIENT_SECRET в панель магазина, живая проверка входа | **можем сделать мы** | наша инженерная часть |

## 2. Что проверить до подачи

Яндекс отказывает программам, нарушающим закон или вредящим его репутации:
«Пользователю запрещается использовать Сервис для авторизации Конечных пользователей через Яндекс ID в случае,
если Программа не соответствует законодательству Российской Федерации» (YA6). Отдельным пунктом запрещены программы,
«которые используют имя и (или) бренд Яндекса в рекламных целях, при этом не являются прямыми партнерами Яндекса» (YA9) —
то есть кнопку входа оформляем строго по конструктору Яндекса, без самодельных надписей «вместе с Яндексом».

## 3. План видео (2 мин)

| Время | Что на экране | Что говорим |
|---|---|---|
| 0:00–0:15 | Витрина, кнопка «Войти с Яндекс ID» | «Покупателю не нужно придумывать пароль — он входит своим Яндексом» |
| 0:15–0:45 | oauth.yandex.ru, создание приложения, выбор типа | «Тип приложения выбирается один раз и не меняется — ставим «Для авторизации пользователей»» |
| 0:45–1:15 | Поля прав доступа и Redirect URI | «Просим только почту и имя. Адреса возврата — все домены вашего магазина» |
| 1:15–1:45 | Кнопка «Подтвердить аккаунт через Госуслуги», переход на Госуслуги | «Этот шаг только ваш: подтверждает Госуслугами владелец бизнеса. По-другому нельзя» |
| 1:45–2:00 | Вход на витрине живьём, экран согласия, личный кабинет покупателя | «Проверяем настоящим входом» |

## 4. Открытые вопросы

- Партнёрской программы у Яндекс ID нет — **сервис бесплатный, монетизации для интегратора в источниках не найдено**.
- Прямого запрета передавать CLIENT_SECRET третьему лицу в прочитанных разделах документации **не найдено в источниках**.
  На практике секрет всё равно храним как платёжный: шифрованным, в пер-тенантном хранилище. **Требует юриста** — в части оферты.
- Вид кнопки и название сервиса на экране согласия — открытый вопрос к Ивану ещё с 2026-09-05, не закрыт.
