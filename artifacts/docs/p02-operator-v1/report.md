## Что теперь работает

Иван пишет одну фразу в поле на странице «Оператор» UI штаба. Дальше без него:

1. `operator.mjs` видит новый файл в `intake/prompts/`, кладёт промпт в `operator.db` дословно;
2. `parse.mjs` зовёт `claude -p --model haiku` со схемой `records.schema.json` — единственное место,
   где на Э1 работает модель. Из свободного текста получаются ЗАПИСИ: тип, область, заголовок и
   дословная цитата Ивана. Нумерованный список «1. … 2. … 3. …» становится тремя записями;
3. `routes.mjs` по типу записи решает, с какого уровня начинать (правило в КОДЕ, не в промпте);
4. `ask.mjs` отвечает скриптом: пассажи из индекса корпуса (FTS5 trigram по 1463 документам) либо
   типовой документ — «статус очереди», «где результат», живая проба `curl`, «как попасть»;
5. `gate.mjs` судит ответ по §5: источник существует на диске, цитата найдена в нём ДОСЛОВНО,
   документ не короче 200 знаков и не называет путей вне источников, у `live` есть замер этого прогона.
   Зелёный — документ уходит в ленту; красный — ответом не показывается, а даёт строку в
   `escalations.log` (вход для Э2);
6. UI рисует ленту: промпт Ивана дословно → карточки записей → документ ответа с плашкой уровня,
   временем, источниками-ссылками и кнопками «ок» / «не то → выше» / «в очередь».

Задачи и баги оператор не «отвечает» — он их готовит и ждёт кнопки Ивана (§9, правило 22j).

## Чего НЕТ и почему

- **Уровни выше `script`.** Э2 по §10. Красный гейт и кнопка «не то» уже пишут строку в
  `escalations.log` — вход готов, потребителя нет. Маршруты `decision`→opus и `bug`→sonnet стоят в
  `routes.mjs`, но на Э1 дают эскалацию вместо ответа.
- **Кнопка «в очередь» не зовёт диспетчер.** Сохраняет `verdict_ivan='queue'`; `add-task` — Э2.
- **Записи `notice` от штаба в ленту** — Э2.
- **Ответы Э1 без прозы.** Документ склеен из дословных пассажей; haiku-compose (4.1.1) — Э2.
- **Шум самоцитирования.** В корпусе лежит и промпт этой задачи (`prompts/p02-operator-v1.md`), где
  все шесть тестовых вопросов выписаны. Он честно попадает в выдачу и иногда занимает верхнюю строку.
  Убирать его по ИМЕНИ нельзя (это тюнинг к файлу); для Э2 правильный ход — понижать пассаж, который
  вопрос ПОВТОРЯЕТ, а не отвечает.
- **Поля `project` в записях нет.** Позиция штаба «один оператор, N очередей»
  (`intake/STAFF-MULTI-PROJECT.md`, пришла в `dev` 23:38, после того как Э1 был собран) требует
  ключа `project` в `records`/`answers` и `answers/<project>/`. Это чистая миграция схемы поверх
  готового: `schema.sql` + одна колонка + фильтр в `passages()` по корням проекта. Делать это до
  слова Ивана «делай» по той спеке не стал (правило 22j, и сама спека это оговаривает).
- **Английский документ по русскому вопросу не находится.** `prompts/_worker-preamble.md` (там стоит
  приказ «только сохранённые копии документации WB») написан по-английски, и trigram по русским
  основам его не достаёт. Вопрос 07:08 всё равно зелёный: ответ пришёл из resume-блока
  `2026-09-16-0809-7b183b97.md`, где штаб отвечал на него вживую и где оба ожидаемых пути
  (`w01-wb-readonly-client/docs`, `w10-marketplace-spec/docs`) стоят внутри проверенной цитаты.
  Двуязычный запрос — кандидат в Э2.

## Экономия

**(а) Шесть вопросов дня — уровень, секунды, источники.** Все шесть закрыты уровнем `script`, ни один
не поднялся выше. Ответ уровня «скрипт»: 21 документ прогона, все зелёные, суммарно **1,04 с**
(в среднем 0,05 с на ответ), **0 токенов** — модель в ответе не участвует вовсе. Ожидаемый источник
найден у всех шести вопросов.

**(б) Разбор промпта haiku.** Поля берутся из JSON-ответа `claude -p --output-format json`: структура
— из `structured_output` (готовый объект, парсить `result` не нужно), расход — из `usage`
(`input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens`,
`output_tokens_details.thinking_tokens`), цена — из `total_cost_usd`.
За прогон: **9 промптов (1 из них — заглушка провала), 107,3 с, в среднем 11,9 с/промпт;
in 80 · cache_creation 14 844 · cache_read 38 984 · out 10 180 · $0,0948 всего, $0,0119 за разбор.**
Провал разбора стоит **0,9 с и $0** — заглушка не зовёт модель вовсе и всё равно даёт запись.

**Найденная экономия, замер на одном промпте:** флаги `--restricted --tools "" --no-session-persistence`
дают **8,6 с и $0,0147** против **32,2 с и $0,134** у того же вызова без них (без флагов в системный
промпт грузятся определения всех тулов: cache_creation 54 298 против 4 819). **В 9 раз дешевле и в
3,7 раза быстрее при том же результате.** Кандидат в правило: любой `claude -p`, которому не нужны
инструменты, зовётся с этими тремя флагами.

**(в) Индекс.** Полная сборка корпуса 12,8 МБ (1463 файла) — **8,8 с**, база **62,5 МБ**;
инкрементальный прогон без изменений — **0,1 с**. `node:sqlite` встроен, ни одной зависимости не
добавлено. Побочный замер: `--full` поверх существующей базы раздувал её до 98,5 МБ (фрагментация
FTS5, `vacuum` не помогает — 97,9 МБ), поэтому `--full` теперь пересоздаёт таблицу FTS с нуля.

**(г) Что автоматизировано вместо глаз и кадров.**
- `intake/testset.mjs` — таблица приёмки шести вопросов одной командой с кодом возврата. Раньше это
  был бы ручной обход UI и шесть кадров; теперь кадры сняты ДЛЯ ВИДА (что Иван увидит), а критерий
  «ожидаемый источник найден» — число.
- `intake/secret-audit.mjs` — проверка секретов скриптом по 158 значениям × 14 файлов вместо чтения
  базы глазами.
- Проверка «каждая ссылка-источник открывается» — 48 запросов скриптом, а не 48 кликов.
- 53 теста поймали ЧЕТЫРЕ дефекта до всякой приёмки: (1) `parse.mjs` читал путь к `claude` при
  загрузке модуля, поэтому подмена бинаря в кэшированном модуле молча оставалась старой; (2) fallback
  на `kind=remark` тоже отбивался `intake.mjs` (замечание без цели и приёмки он не берёт) — вместо
  подмены типа записи отказ теперь честно виден в карточке; (3) гейт краснел на `/compact` и
  `opus/high` как на «путях»; (4) гейт краснел на пути внутри ПРОВЕРЕННОЙ цитаты.
- Критик-раунд не понадобился ни разу: каждый отход от спеки закрыт тестом, который его проверяет.

**(д) Что автоматизировать следующим ходом.**
