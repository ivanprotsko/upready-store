## Расхождение с текстом acceptance — числа устарели, суть держится

В acceptance задачи записано «вход `admin@acme.test` → 4 товара Acme, вход `admin@globex.test` →
2 товара Globex». На стенде сейчас **6 и 3**. Причина не в панели: скрипт
`apps/backend/scripts/mt-live-scenario.mjs` создаёт при каждом прогоне новую пару товаров с суффиксом
прогона — в базе лежат серии `(live)`, `(live mtvmilw5)`, `(live mtvwemqw)`. Проверяемая суть критерия
— «своих видно всё, чужих ноль» — не изменилась; при приёмке сверяются списки по владельцу, а не
числа 4 и 2. Правку самого текста acceptance делает Иван (22j), сессия его не трогает.

## Подводный камень стенда, найденный до приёмки: кэш витрины

`apps/storefront/src/lib/data/products.ts` читает каталог с `cache: "force-cache"` и тегом `products`.
Событий из Medusa в витрину не приходит, поэтому **новый товар не появляется на витрине сам** — до
приёмки два товара серии `mtvwemqw` уже лежали в API и не были видны ни на одной витрине.

Следствие для критерия «товар из панели виден на :8000 и не виден на :8001/:8002»: проверка «не виден
у соседа» без сброса кэша не доказывает ничего — сосед мог просто отдать старую страницу. Сбрасывается
штатным вебхуком витрины:

```
curl -s -X POST http://localhost:8000/api/revalidate -H 'content-type: application/json' \
  -d '{"type":"product.created"}'   # то же для :8001 и :8002
```

Проверено: до вызова :8000 показывал 4 карточки, после — 6.

## Заказ с витрины: инструмент проверен на живом заказе

Критерий про заказы проверяется не через store API, а через саму витрину — вход в поток с его начала
(18f). Сценарий проведён браузером на :8000 целиком: каталог → карточка товара → в корзину →

Результат прогона 04:42: заказ **#6** `order_01M26GXCR6FXXEHHEY013YZVGS`, страница подтверждения
`http://localhost:8000/en/order/order_01M26GXCR6FXXEHHEY013YZVGS/confirmed`. Сразу после — списки
заказов тенантов: у Acme 6 заказов, новый в списке; у Globex 0; у Initech 0.

Замеченное по дороге (пригодится тому, кто будет повторять): кнопка «в корзину» приходит из SSR
раньше, чем React вешает обработчик, — клик в первую секунду молча ничего не делает, и `/en/checkout`
отвечает «Page not found», потому что корзины нет. Сценарий делает паузу на гидратацию и проверяет
корзину, повторяя до трёх раз.
