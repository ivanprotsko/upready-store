# Composer: стенд-конструктор главной с сохранёнными версиями

Задача `t-2026-09-09-01` (2026-09-09, день). Стенд: `node artifacts/docs/composer/serve.mjs` →
**http://localhost:8303**. Заказ Ивана: «стенд, на котором я смогу переключаться между темами,
светлой и тёмной версией, версиями hero, футера, хедера и т.д.; сохранить версию и подписать её,
чтобы ты потом мог посмотреть сохранённые версии и сделать для них скриншоты, чтобы обновить
карточки на сайте upready.dev».

## 1 · Что это

Две лаборатории ночи — hero-lab-2 (:8301, шесть hero G–M) и blocks-lab (:8302, P1–P5, H1–H5,
F1–F5, GA/GB) — показывали варианты по одному, каждый в своём контексте. Composer собирает из тех
же вариантов **целую главную** в порядке storefront: промо-полоса + хедер → hero → плитки категорий
→ выкладка → футер, в любой из пяти тем, в light или dark, на 1440 или 390. Сборку можно сохранить
под подписью; сохранённое лежит в `composer/versions.json` и снимается `shoot.mjs` в формат
карточек upready.dev.

Стенд ничего не сочиняет: `/data.json` собирается из `profiles/<id>/` так же, как в blocks-lab
(profile.json, theme.json, catalog/*.json, оба режима темы), плюс таблица «какие кадры есть у
бренда» из hero-lab-2 для hero L. Разметка вариантов **не переписана**: `lib/blocks.js`,
`lib/blocks.css`, `lib/hero.js`, `lib/hero.css`, `lib/measure.js` вырезаны из `index.html` двух
лабораторий по строкам (источник и коммит в шапке каждого файла) — то, что Иван видел на :8301 и
:8302, и то, что собирает composer, один и тот же код.

## 2 · Дизайн-стадия (правило 27d)

Канон — `~/upready/packages/geist-kit/AGENTS.md`: нейтральный chrome лаборатории, как у blocks-lab
(тёмная панель, hairline-границы, моно для id и метрик, sentence case, вес ≤ 600, один акцент).
Бренд живёт только внутри `.store`. Макет:

```
┌ рейка 320 ───────────────┬ сцена ─────────────────────────────────────────────┐
│ Composer · стенд          │ Kerbstone · dark · H2 · K · tiles · P3 · F2 · v-…  │
│ БРЕНД  sne Kerbstone ●    │ ● 57 узлов · запас 6.7:1 при 4.5   1440 px · ×0.93 │
│        ele Ferrite        │ ┌────────────────────────────────────────────────┐ │
│ РЕЖИМ  light | dark ●     │ │ промо-полоса · хедер                           │ │
│ ШИРИНА 1440 ● | 390       │ │ hero                                           │ │
│ ХЕДЕР  H1 … H6            │ │ Categories · плитки                            │ │
│ HERO   NONE G H J K L M   │ │ выкладка                                       │ │
│        GA GB              │ │ футер                                          │ │
│ ПЛИТКИ есть | нет         │ └────────────────────────────────────────────────┘ │
│ ВЫКЛАДКА NONE P1 … P5     │                                                    │
│ ФУТЕР  NONE F1 … F6       │                                                    │
│ ВЕРСИЯ [подпись] [заметка]│                                                    │
│ (Сохранить версию)        │                                                    │
│ СОХРАНЁННЫЕ · 3           │                                                    │
│ ▸ подпись            ●    │                                                    │
│   v-20260909-…  brand·mode│                                                    │
│   открыть · без рамки ↗   │                                                    │
│   переименовать · удалить │                                                    │
└───────────────────────────┴────────────────────────────────────────────────────┘
```

Сцена масштабирует страницу под ширину окна (`transform: scale`, коэффициент виден рядом с
шириной), чтобы 1440 px помещались без горизонтальной прокрутки; «без рамки ↗» открывает ту же
сборку в 1:1 без chrome. Точка у версии — состояние кадра: серая «не снят», зелёная «снят»,
жёлтая «снят до последней правки».

## 4 · Как пользоваться

1. `node artifacts/docs/composer/serve.mjs` (если :8303 не отвечает) → открыть http://localhost:8303.
2. Щёлкать рейку: бренд, режим, ширина, пять слотов. Сцена перерисовывается сразу, чип показывает
   худший контраст текста на плоском фоне по всей странице (метод тот же, что в лабораториях).
3. Подпись → «Сохранить версию». Версия получает id `v-<дата>-<подпись транслитом>` и появляется в
   списке; адрес страницы становится `#v=<id>` — его можно прислать в чат.
4. Открытая версия: «Обновить <id>» перезаписывает её текущей сборкой; «Сохранить как новую» —
   вторая запись; «Сбросить» отвязывает, чтобы правки не трогали сохранённое.
5. В списке: «открыть» — загрузить в рейку; «без рамки ↗» — 1:1 в новой вкладке; «переименовать» —
   поле на месте, Enter; «удалить» — два клика в течение трёх секунд (кадры в `shots/` остаются).

## 5 · Реестр версий

`artifacts/docs/composer/versions.json` — JSON (правило 18b), в git:

```json
{
  "schema": "upready.composer-versions/v1",
  "versions": [
    {
      "id": "v-20260909-kerbstone-tyomnyy-k-spisok",
      "label": "Kerbstone тёмный, K + список",
      "note": "что смотреть в этой версии",
      "createdAt": "2026-09-09T19:32:10+08:00",
      "updatedAt": "2026-09-09T19:34:02+08:00",
      "spec": { "brand": "sneakers", "mode": "dark", "width": "desktop",
                "header": "h2", "hero": "k", "tiles": "on", "listing": "p3", "footer": "f2" }
    }
  ]
}
```

`spec` проверяется на сервере тем же `validateSpec`, что в браузере: значение вне коридора —
400 с именем слота и списком допустимого, файл не трогается. Запись атомарная (tmp + rename).

## 6 · Съёмка и карточки upready.dev

```
node artifacts/docs/composer/shoot.mjs            # версии без кадра или с кадром старше правки
node artifacts/docs/composer/shoot.mjs --all      # все заново
node artifacts/docs/composer/shoot.mjs <id> …     # выбранные
```

Десктоп: `/view?v=<id>` в окне 1440×1920 (кадр рецепта карточек) → `shots/<id>.png`, затем
`magick … -resize 960x1280! -quality 82 -define webp:method=6` → `shots/<id>.webp` — ровно вызов
из `upready-dev/artifacts/docs/recipe-showcase-cards.md` §1.1. Мобильная версия снимается 390×520
при 2× и апскейлится до 960×1280 — скрипт пишет об этом в строке. `shots/` вне git.

Дальше по рецепту карточек: положить webp в `upready-dev/images/demo-<slug>.webp`, пять точек
касания в `index.html` (§1.2–1.5), `check-showcase.mjs`, коммит; push и выкат — только по команде.

## 8 · Границы и развилка

Composer собирает **макетную** разметку лабораторий с настоящими данными, не код storefront.
Кадр из `shots/` показывает, как сборка выглядит, а не как её отрендерит Next.js. Сегодня карточки
на upready.dev сняты с живых стендов. Два пути к обновлению карточек из сохранённых версий:

- (a) карточки из макетов сейчас — быстро, но на лендинге будет то, чего в продукте ещё нет;
- (b) выбранные версии сначала уходят в storefront как профильные оси (schema + types +
  build-profile + компоненты — ход, который уже ждёт ответа в `q-blocks-lab-corridor-choices`),
  потом стенды пересъёмка `landing-shots/shoot.mjs`.

Это вопрос `q-composer-cards-from-mock-or-code`. Стенд полезен в обоих случаях: в (a) он источник
кадров, в (b) — спецификация того, что нести в код (`spec` версии и есть список профильных осей).
