# Тестовый UI «оплата → онбординг» на shiftship.dev — требования Ивана (2026-09-12, ночь)

Заказ дословно: «по адресу `www.shiftship.dev` и `shiftship.dev` я вижу текст "Bad gateway", давай
там разместим тестовый UI для перехода на сценарий тестовой оплаты». Ниже — четыре входа, которые
он назвал, и прямой вход в онбординг.

## Что должно открываться с холодного старта

Одна страница-витрина сценариев на `shiftship.dev` (и `www.`), каждая карточка — рабочий вход:

1. **Прямая оплата.** Перейти к тестовой оплате → ввести данные карты → нажать «Оплатить» →
   попасть на страницу онбординга с настройками своего магазина.
2. **Услуга + тариф.** Выбрать услугу, затем тариф → оплата (как в п.1) → онбординг.
3. **Только тариф.** Услуга подразумевается единственной: выбор тарифа → оплата → онбординг.
4. **Только услуга.** У услуги подразумевается единственный тариф: выбор услуги → оплата →
   онбординг.
5. **Онбординг напрямую** — отдельная ссылка, входящая в сценарий онбординга без оплаты.

Смысл набора: Иван сравнивает ЧЕТЫРЕ формы воронки на одном стенде, а не одну «правильную».
Каждая карточка ведёт в свой поток целиком, не в заглушку.

## Приёмка (правило 18f + 27d)

- Живой продукт: `https://shiftship.dev` и `https://www.shiftship.dev` открываются в браузере с
  сертификатом, витрина сценариев видна глазами (скриншот — факт о файле, не вердикт).
- Каждый из четырёх входов проходится ЦЕЛИКОМ от холодного старта до экрана онбординга с
  настройками магазина; ни один не требует знать трюк.
- Тестовая оплата действительно отклоняется на `0000…` и проходит на нормальном номере — оба исхода
  показаны.
- Прямая ссылка на онбординг работает отдельно от оплаты.
- Дизайн-стадия перед кодом: канон Geist (`~/upready/packages/geist-kit/AGENTS.md`), макет назван в
  задаче до начала вёрстки.
