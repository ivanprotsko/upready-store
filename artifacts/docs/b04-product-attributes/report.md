## 1. Схема по умолчанию (семь характеристик)

`apps/backend/src/product-attributes-fill/default-schema.ts`. Шесть имён из задачи, где
«объём/вес» разложен на две строки — миллилитры и граммы не делят одну колонку и одну единицу.

| Ключ | Название | Тип | На карточке | В фильтрах |
|---|---|---|---|---|
| `sku` | Артикул | текст | да | нет |
| `composition` | Состав | текст | да | нет |
| `volume` | Объём, мл | число | да | **да** |
| `weight` | Вес, г | число | да | нет |
| `country` | Страна производства | выбор | да | **да** |
| `shelf_life` | Срок годности | текст | да | нет |
| `purpose` | Назначение | текст | да | нет |

Фильтруемых ровно два, и это решение, а не недоделка: фильтр стоит чипа в каталоге, только если
покупатель выбирает из короткого списка. Страна — такой список (четыре значения на весь каталог),
объём — диапазон. Состав, назначение и срок годности — свободный текст в десяток слов: они дали бы
сотню чипов по одному товару каждый. Артикул ищут, а не перебирают.

Срок годности намеренно ТЕКСТ. Каталог пишет его в трёх единицах — «60 месяцев», «5 лет» и голое
«1825» под именем «Срок годности в днях». Пересчёт в месяцы дал бы «25 месяцев» там, где владелица
написала «750 дней»: число, которого нет ни на упаковке, ни в её карточке.

Набор ставится двумя путями, оба идемпотентны и оба зовут одну функцию
(`apply-default-schema.ts` → `ensureDefaultSchema`):

- кнопка «Добавить стандартные» на экране «Характеристики» панели (`POST /tenants/product-attribute-presets`);
- сам скрипт заполнения, первым шагом.

Существующая характеристика не трогается никогда: решение принимается по `key` — единственной
колонке, которую панель не даёт править. Владелица переименовала «Объём» или сняла с него фильтр —
следующий прогон это сохранит.

## 2. Скрипт заполнения

`apps/backend/src/scripts/backfill-product-attributes.ts`, парсер —
`apps/backend/src/product-attributes-fill/parse-characteristics.ts`.

```
npx medusa exec ./src/scripts/backfill-product-attributes.ts cherkashino [dry-run] [overwrite] [report=<path>]
```

Аргументы без ведущих дефисов: `medusa exec` разбирает командную строку сам и отвечает
«Unknown arguments: tenant, dry-run» на любой незнакомый флаг (замер на Medusa CLI 2.19). У каждого
аргумента есть env-двойник (`TENANT_HANDLE`, `DRY_RUN`, `OVERWRITE`, `REPORT_PATH`) — форма для
`docker exec` на общем движке.

Источники, в порядке доверия; каждый следующий закрывает только то, что предыдущий не заполнил:

1. `metadata.full_characteristics` — карточка маркетплейса, две формы: `{name, value}` (Ozon) и
   `{name, values:[…]}` (WB). Парсер читает ещё и строки «Ключ: значение», и уже разобранный
   массив, и простой объект.
2. `metadata.short_characteristics` — короткая карточка того же маркетплейса.
3. `metadata.composition`, `metadata.application` — то, что миграция вынесла из описания.
4. Название варианта — «Зубная паста тайская с гвоздикой, **30 гр**», «Мазь…, **100 мл**». Берётся
   последняя величина с ЯВНОЙ единицей массы или объёма, поэтому «60 шт» не даёт ничего, а «АСД 2
   фракция…, 100 мл» даёт 100 мл, а не 2.
5. SKU варианта — как артикул, если в карточке его нет.

Нормализация: шесть написаний одного факта сводятся к одному ключу («Страна производства» и
«Страна-изготовитель»; «Вес (без упаковки)» предпочитается «Весу (с упаковкой)» независимо от
порядка в карточке), единицы приводятся (0,3 кг → 300 г; 2 л → 2000 мл; «60» под именем «Объем, мл»
→ 60 мл), единица чужой величины отвергается (0,3 кг под объёмом — не 300 мл).

Что скрипт НЕ делает:

- не выдумывает значений. Имя, которому в схеме нет места, и значение, не являющееся числом там,
  где нужно число, попадают в отчёт, а не в каталог;
- не затирает правку владельца. Значение, отличное от каталожного, считается и остаётся
  (`values left as the owner typed them`). `overwrite` — для случая импорта;
- не выходит за тенанта: товары берутся по связи tenant-product.

считает товары, которые каталог ОПИСАЛ: **30 из 38**. Восемь оставшихся — те, у кого в каталоге нет

  набор на месте: 7 характеристик» либо «Из стандартного набора не хватает N из 7: …». Кнопка

- **Список товаров** — строка «Характеристики заполнены у 38 из 38 товаров», ссылкой на раздел
  характеристик (скриншот 02). Счёт по всему каталогу, а не по странице: владелица заполняет его
  за несколько заходов, и постраничное число никогда бы не сошлось.
  Источник — `GET /tenants/product-attribute-coverage`:
  `{"products_total":38,"products_filled":38,"attributes_total":7,"per_attribute":{"Артикул":38,"Вес":20,"Страна производства":17,"Состав":14,"Срок годности":14,"Объём":7,"Назначение":5}}`
- **Карточка товара** — секция «Характеристики» с заполненными значениями (скриншот 03); редактор
  значений — экран t15, не менялся.

Полный цикл кнопки проверен на стенде: характеристика «Назначение» удалена через API
(`deleted: true`) → `GET /tenants/product-attribute-presets` вернул `missing: 1 Назначение` →
`POST` вернул `created: ['purpose']`, повторный `POST` — `created: []` → прогон скрипта вернул её
пять значений (`values created: 5`).

## Что не сделано и почему

- **Живой хост не трогали.** Заполнение на `medusa_mt` — отдельная run-задача после деплоя, как
  сказано в постановке. Команда для неё:
  `docker exec mt-backend node_modules/.bin/medusa exec ./src/scripts/backfill-product-attributes.js cherkashino`
  (сначала с `dry-run` и `report=…`).
- **Габариты упаковки** (24 значения в каталоге) в набор не вошли: в задаче их нет, а три отдельные
  характеристики в наборе по умолчанию для всех магазинов — решение шире этой задачи.
- **Единица характеристики не переводится.** В английском ответе `unit` остаётся «мл»/«г» — колонка
  `unit` в модели t15 не `.translatable()`. Это поведение t15, не регресс; чинить — отдельной
  правкой модели и миграцией.
- **39-й товар живой базы** в клоне отсутствует (клон от 2026-09-12). На живом прогоне он
  обработается наравне с остальными.
