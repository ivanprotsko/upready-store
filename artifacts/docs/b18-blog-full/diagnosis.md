## Диагноз

Причина ровно одна и она продуктовая: **точка входа в журнал — адрес, а не статья.**

1. Единственный способ начать статью — форма, которая первым делом требует slug
   («Адрес статьи»), причём по правилам бэкенда (`ARTICLE_SLUG`, `validators.ts:136`)
   это латиница-цифры-дефисы. Владелица пишет по-русски и слово «slug» не знает.
2. `POST /tenants/articles` по построению создаёт ПУСТУЮ строку (`body: ""`, `published:false`) —
   то есть создание и написание разнесены на два шага, и первый из них бессмысленный для человека.
3. Редактор живёт в модалке `/journal/:slug` и виден только после шага 1. При нуле статей
   пользователь никакой «страницы для статьи» не видит вовсе — что и написал Иван.
4. Заодно у журнала нет того, что делает его блогом: нет превью markdown (текст пишется
   вслепую в `<Textarea rows={24}>`), нет загрузки картинок ВНУТРЬ текста (загружается только
   обложка), нет статусов кроме «опубликована/нет» (нет отложенной публикации), нет рубрик,
   нет фильтра и поиска в списке, нет ссылки «открыть на сайте», на витрине нет рубрик,
   времени чтения, похожих статей, шаринга и хлебных крошек.

## Что из этого делается в задаче

- Точка входа: кнопка «Новая статья» открывает **полноценную страницу редактора**, где первое
  поле — заголовок, а адрес генерируется из него сам (и остаётся редактируемым).
- Редактор: markdown + живое превью, загрузка картинок в текст, обложка, рубрика, метки,
  статус черновик/опубликована/по расписанию, SEO, автор, переключение языков, «открыть на сайте».
- Список: фильтр по статусу, поиск, рубрика.
- Бэкенд: поля `status`, `category`, `author`, отложенная публикация, рубрики, фильтрация в store API.
- Витрина: рубрики, время чтения, похожие статьи, шаринг, хлебные крошки, OG.
