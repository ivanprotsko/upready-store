## Эталон, как он устроен

`templates/index.tsx` (162 строки) выкладывает блоки в `ProductGridFrame` — сетку, чьи
брейкпоинты берутся из ШИРИНЫ САМОЙ СЕТКИ (ResizeObserver), а не из ширины окна:

| bp | ширина сетки | колонки |
|---|---|---|
| base | < 512 | одна, всё стопкой |
| xsmall | 512–1023 | галерея \| сводка; карточка покупки под обеими |
| small | 1024+ | галерея \| сводка \| липкая карточка покупки (до 22rem) |

Порядок блоков внутри: хлебные крошки → галерея (кол. 1) → сводка (кол. 2) → остаток склада →
CTA онбординга + цена и «В корзину» (кол. 3) → описание → состав → отзывы (кол. 1–2, ряд 2).

## Механика галереи — что именно переносится

Список взят из `index.test.tsx` эталона (там он и объявлен контрактом) плюс из кода:

1. первый кадр активен при открытии — это белая обложка, её порядок не меняем (приказ Ивана w07 04:44);
2. клик по миниатюре переключает герой;
3. стрелки next/prev ходят по кругу (`wrapIndex`);
4. клик по точке прыгает на свой кадр; точек не больше семи, дальше — окно вокруг активной;
5. смена списка картинок (вариант товара) сбрасывает активный кадр на первый;
6. у товара с одной картинкой навигации нет вовсе;
7. ряд точек не перехватывает клики в пустотах (`pointer-events-none` на ряду, `auto` на точке);
8. свайп с порогом 40 px, захват указателя только после 6 px движения — обычный тап проходит насквозь;
9. лайтбокс: клик по герою открывает, Esc и крестик закрывают, скролл страницы заблокирован;
10. ArrowLeft/ArrowRight — в лайтбоксе всегда, на странице пока фокус внутри галереи;
11. соседние кадры прогреваются в кэше браузера;
12. коробка героя держит пропорцию (`metadata.aspect_ratio`, по умолчанию 3/4) и после `onLoad`
    переходит на настоящую пропорцию активного снимка — страница не прыгает.

Не переносим: зум с перетаскиванием внутри лайтбокса, анимацию «карусель с подглядыванием»
соседних кадров, вертикальные стрелки прокрутки ленты, вырезанный фон (`cutoutUrl`) —
у нас нет источника таких картинок.
