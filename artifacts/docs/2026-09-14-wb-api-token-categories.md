# WB API-токен: где взять и какие категории нужны для миграции с Wildberries и функций уровня inSales

Дата: 2026-09-14 16:34 WITA · ветка `chore/marketplace` (upready-store) · сессия Claude Code.
Контекст: в проекте chrxnasdmds (магазин Оксаны Черкашиной, «Фабрика Натуральных Продуктов») каталог и отзывы с WB собирались с публичных эндпоинтов, потому что Seller API владельца был недоступен. ## 1. Где взять токен — инструкция, две версии сверены

Сверялись две официальные страницы:

- Инструкция продавца: «Как подключиться по API через токен» + подстатья «Как создать, обновить или удалить токен WB API» (seller.wildberries.ru, обновлено 18.05.2026).
- Документация разработчика: «API information → Authorization → How to create a personal access, base, or test token» + «Token categories» (dev.wildberries.ru).

**Противоречий нет.** Обе страницы описывают один и тот же путь и одни и те же поля. Текст Ивана из пункта 1.1 дословно совпадает с русской версией dev-документации. Разница только в полноте: инструкция продавца подробнее про типы токенов и безопасность, dev-документация — про JWT, коды ошибок и лимиты запросов.

**Внимание, устаревшее у нас:** zettel `lab/docs/qa/202609040215-wb-api-tokens-howto.md` (04.09) описывает старый интерфейс «Настройки → Доступ к API» с флажками «Только на чтение» и «Тестовый контур». Сейчас это раздел «Интеграции по API», тип токена выбирается вкладкой, а уровень доступа — переключателем. Старые токены продолжают работать как «базовые» до истечения срока (dev.wildberries.ru/news/148).

### 1.1. Шаги (сводная версия по двум источникам)

1. Войти в WB Partners (seller.wildberries.ru) **как владелец профиля**. Сотрудники токены создавать и удалять не могут.
2. Профиль → раздел **«Интеграции по API»** → кнопка **«+ Создать токен»**.
3. В окне две вкладки: «Для сервиса из каталога» (сервисный токен) и **«Для интеграции вручную»** — нам нужна вторая.
4. Выбрать **тип токена**. Для нас — **базовый** (обоснование в 1.2).
5. Заполнить **название** (например, «upready — миграция магазина» или «upready — магазин и заказы»).
6. Отметить галочками **категории данных** (список в разделе 3). После создания категории изменить нельзя — только создать новый токен.
7. Выбрать **уровень доступа**: «чтение и запись» или «только чтение». Уровень один на весь токен, не на категорию.
8. Комментарий (необязательно) → «Создать» → **«Скопировать и закрыть»**. Токен показывается **один раз**; при утере — удалить и создать новый.
9. Передать токен нам защищённым каналом (не в мессенджере открытым текстом). У нас он ложится в `~/upready/.env.keys` (правило 2a).

Ограничения, одинаковые в обоих источниках: срок действия **180 дней** (уведомление владельцу за 3 дня, продление = «Дублировать» и заменить в интеграции), **до 20 активных токенов** на профиль, смена номера телефона владельца **отзывает все токены**. Инструкция продавца дополнительно **не рекомендует больше 3 категорий** в одном персональном/базовом токене, но её же сценарий «Комплексное управление магазином» перечисляет 8 категорий — это рекомендация, не ограничение.

### 1.2. Какой тип токена: базовый

| Тип | Для чего по документации | Нам подходит? |
|---|---|---|
| Сервисный | Только облачный сервис из Каталога бизнес-решений WB; категории подставляются автоматически | Нет — upready в Каталоге нет |
| Персональный | Своё ПО и коробочные системы на инфраструктуре продавца; **прямо запрещён для облачных сервисов** | Нет — upready-store работает в нашем облаке |
| **Базовый** | «Все остальные случаи, когда сервисный и персональный не подходят», в т.ч. тест интеграции на реальных данных | **Да** |
| Тестовый | Только песочница, сгенерированные данные, все категории сразу | Только для разработки, миграцию не сделает |

Базовый токен сейчас даёт те же категории, что персональный, кроме **«Пользователи»** (dev.wildberries.ru/news/148, инструкция «Категории данных»). WB предупреждает, что «в будущем» часть категорий останется только в персональных токенах — какие именно, не названо; отслеживать через `updates`.

### 1.3. Как проверить, что токен рабочий и с нужными категориями

- `GET https://<хост категории>/ping` с заголовком `Authorization: <token>` → `{"Status":"OK"}`. Хосты: `content-api`, `discounts-prices-api`, `marketplace-api`, `seller-analytics-api`, `statistics-api`, `feedbacks-api`, `finance-api`, `advert-api`, `buyer-chat-api`, `supplies-api`, `returns-api`, `documents-api` — все `.wildberries.ru`. Лимит `/ping`: 3 запроса за 30 секунд.
- Ответ **401** на рабочем методе = категория токена не совпадает с категорией метода (dev-документация, раздел ошибок).
- Токен — JWT (RFC 7519): категории видны при декодировании. WB просит не декодировать онлайн-инструментами.

### 1.4. Готовое сообщение продавцу (скопировать как есть)

> Оксана, чтобы перенести магазин с Wildberries, нужен API-токен. Он создаётся только владельцем кабинета WB Partners за 2–3 минуты:
> 1. seller.wildberries.ru → имя профиля → «Интеграции по API» → «+ Создать токен».
> 2. Вкладка «Для интеграции вручную» → тип «Базовый токен».
> 3. Название: «upready — миграция магазина».
> 4. Категории (галочки): Контент, Цены и скидки, Маркетплейс, Вопросы и отзывы, Аналитика, Статистика.
> 5. Уровень доступа: «Только чтение».
> 6. «Создать» → «Скопировать и закрыть» и сразу прислать токен нам в защищённом виде — второй раз WB его не покажет.
> Токен ничего не меняет в магазине, только читает данные. Его можно удалить в том же разделе в любой момент, когда перенос закончится.

## 3. Список категорий токена: что отмечать и с каким доступом

Формат: **Заголовок (категория на скриншоте) → пункт**. Колонка «Миграция» — обязательно ли для успешного переноса магазина в upready-store. Колонка «read-only?» — замер по `x-readonly-method` в спеках WB: проходит ли нужный нам вызов по токену «только чтение».

|---|---|---|---|---|---|
| 1 | **Контент → Карточки товаров** | Все карточки продавца: названия, описания, характеристики, размеры, баркоды, ссылки на фото/видео | **ОБЯЗАТЕЛЬНО** | чтение (+ запись для редактирования с нашей стороны) | `POST /content/v2/get/cards/list` — да; `POST /content/v2/cards/update` — нет |

### 3.1. Минимум для успешной миграции

Галочки в одном токене «только чтение»: **Контент, Цены и скидки, Маркетплейс, Вопросы и отзывы, Аналитика** (+ **Статистика**, если хотим показать историю продаж сразу). Категории отмечаются целиком — отдельные пункты внутри категории WB не разбивает.

Замер по спекам: все методы, которые вызывает миграция, помечены `x-readonly-method: true` — карточки, справочники, цены, склады, остатки продавца, остатки WB, отзывы, вопросы, заказы и продажи. Токена «только чтение» достаточно, писать в магазин продавца при переносе не нужно.

### 3.2. Рекомендуемая схема токенов (уровень доступа один на токен)

| Токен | Уровень | Категории | Кто и когда |
|---|---|---|---|
| A. «upready — миграция и аналитика» | только чтение | Контент, Цены и скидки, Маркетплейс, Вопросы и отзывы, Аналитика, Статистика, Финансы, Продвижение | Продавец создаёт первым; хватает для переноса и всех отчётов уровня inSales. После переноса можно оставить для аналитики |
| B. «upready — магазин и заказы» | чтение и запись | Контент, Цены и скидки, Маркетплейс, Вопросы и отзывы (+ Чат с покупателями) | Только когда включаем управление карточками, ценами, остатками, заказами и ответами на отзывы из нашей панели |

Почему два: WB сама советует отдельный токен на задачу и минимум категорий, а «чтение и запись» с Финансами в одном токене — лишний риск. Токен B без Финансов/Аналитики ничего лишнего не откроет при утечке.

### 3.3. Что проверить живым вызовом при приёмке (правило 18f)

1. `/ping` на `content-api`, `discounts-prices-api`, `marketplace-api`, `feedbacks-api`, `seller-analytics-api`, `statistics-api` с токеном A → шесть `OK`.
2. `POST /content/v2/get/cards/list` → число карточек совпадает с кабинетом (у Оксаны ожидаем порядка 221 живой карточки по срезу 31.08).
3. `GET /api/v1/feedbacks` постранично → общее число отзывов больше публичного потолка (у Оксаны публично ≈24,7 тыс. из 107,7 тыс.).
4. `GET /api/v3/warehouses` + `POST /api/v3/stocks/{warehouseId}` → остатки не равны заглушке «46» у всех подряд.
5. Лимиты: в категории «Маркетплейс» ответ 4xx засчитывается как 10 запросов — миграция сначала читает справочники, потом бьёт по складам, без перебора наугад.
