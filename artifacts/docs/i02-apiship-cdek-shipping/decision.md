## Замеры, на которых стоит решение

ApiShip, боевой токен (`probes/apiship-*.json`, `probes/_counts.json`):

```
GET  /v1/lists/providers   → 200, полный каталог перевозчиков
GET  /v1/connections       → 200, rows=1 — подключён ровно ОДИН перевозчик: cdek (id 39452)
GET  /v1/lists/tariffs      → 200, 107 тарифов cdek
GET  /v1/lists/points       → 200, meta.total=10329, координаты у 1000/1000 отданных
POST /v1/calculator         → 200, {"deliveryToDoor":[{"providerKey":"cdek","tariffs":[]}],
                                     "deliveryToPoint":[{"providerKey":"cdek","tariffs":[]}]}
```

Калькулятор пуст во **всех** четырёх комбинациях (`default`, `door-door`, `door-point`,
`point-point`) и не меняется, если передать `cityGuid` обоих городов, взятые из самого же
каталога точек (`probes/apiship-calc-guids.json`). Ошибки в ответе нет — HTTP 200 и пустой
массив. То есть провайдер ApiShip (хоть наш, хоть gorgojs) сегодня показал бы на чекауте
пустой список способов доставки, молча.

Против замера 2026-08-22 (README chrxnasdmds) картина сдвинулась ровно наполовину: тогда
`/connections` отдавал `rows: []` и `/lists/points` — 400 «У Вашей компании нет подключенных СД»;
сегодня СДЭК подключён и точки отдаются, но тарификация по-прежнему не работает. Это настройка
на стороне кабинета ApiShip (договор/тарифы на подключении), кодом не лечится.

CDEK API v2 напрямую, оба контура (`probes/cdek-*.json`):

POST /v2/calculator/tarifflist (Москва 44 → СПб 137, 1 кг)

        песочница→ 200, 17 тарифов; «Посылка склад-склад» 185 ₽, 1-2 дня

GET  /v2/location/cities?city=Санкт-Петербург → 200, code 137

## Решение

**Свой fulfillment-провайдер поверх прямого клиента CDEK API v2** (`cdek_cdek`), реквизиты — по
тенанту в уже существующей таблице `tenant_integration_secret` (инфраструктура из t03, читатель
`src/tenant-secrets/`), переключатель песочница/бой в панели.

Почему не gorgojs, при том что Иван назвал их первыми («через модуль интеграций или без него —
мне не важно; главное чтобы всё было настроено и **отражено на чекауте**»):

1. Их провайдер считает цену тем же вызовом ApiShip, который нашему аккаунту отдаёт ноль тарифов.
   На чекауте это ноль способов доставки — то есть прямо не то, что заказано.
2. Реквизиты у них — одна регистрация на весь инстанс, настраиваемая в Medusa Admin. У нас
   мультитенант, владелец магазина живёт в своей панели и в Admin не ходит. Тот же вывод для
   Robokassa сделала задача i01 (PR #85), здесь он подтверждён по коду конкретно ApiShip-пакета.
3. Вебхуков статусов у них нет вовсе, а заказ Ивана их называет.

ApiShip при этом не выбрасывается: клиент CDEK прячется за узким интерфейсом перевозчика, так что
второй перевозчик (ApiShip как агрегатор, Почта России) добавляется отдельным файлом, когда в
кабинете ApiShip заработает тарификация. Что именно для этого нужно сделать человеку — в конце
`report.md`.

## Что из этого следует для приёмки

Приёмочный критерий задачи «чекаут показывает рассчитанные тарифы СДЭК (курьер + ПВЗ) для реального
адреса» достижим на прямом CDEK и недостижим на ApiShip сегодня — ни нашим кодом, ни gorgojs.
