Запасной вариант из брифа — «сделать подсказки через собственный suggest Яндекс-карт тем же ключом» —
**отбит замером**: наш ключ 2.1 покупает только КАРТУ.

```
# в браузере, с нашим ключом
{"apiLoaded": true, "hasSuggest": true, "hasGeocode": true,
 "suggest":  {"ok": false, "error": "Suggest is not available. See …/ref/reference/suggest"},
 "geocode":  {"ok": false, "error": "scriptError"}}

# те же API по HTTP, тот же ключ
geocode-maps.yandex.ru/1.x/   → 403 {"statusCode":403,"error":"Forbidden","message":"Invalid api key"}
suggest-maps.yandex.ru/v1/    → 403
```

Поэтому подсказки сделаны на справочнике, права на который у магазина ЕСТЬ, — на собственном
справочнике городов СДЭК (эндпоинт `/store/cdek/cities` от i02, живой на реквизитах тенанта).
Провайдера не выдумывал: улицы и дома требуют платного сервиса, и это записано ниже в «что не сделано».

## Что сделано

**Карта пунктов выдачи** — `apps/storefront/src/modules/checkout/components/checkout-pickup-map/index.tsx`
(новый). Яндекс JS API 2.1 (ключ `NEXT_PUBLIC_YANDEX_MAPS_KEY` = канон `IVANPROTSKO_YANDEX_MAP_KEY_ONE`),
`ObjectManager` с кластеризацией, скрипт грузится один раз на жизнь страницы (модульный промис + id
тега), колесо мыши не перехватывается, `prefers-reduced-motion` = перелёт без анимации,
`ResizeObserver` на смену размера. Порядок координат в 2.1 — `[широта, долгота]`, обратный GeoJSON;
на это есть отдельный ассерт в тесте.

**Лист выбора пункта** — `…/checkout-cdek-point-sheet/index.tsx`: слева список (как был), справа
карта; на мобильном — вкладки «Список»/«Карта», список по умолчанию. Клик по метке открывает карточку
пункта (название, адрес, часы, телефон, цена и срок способа) с кнопкой «Выбрать»; выбор ставит способ
доставки с его ценой. Цена и срок приходят из секции доставки (`priceLabel`/`termLabel`), а не
считаются в листе заново — одна цена на карточке способа и в листе.

**Подсказки адреса** — `apps/storefront/src/modules/common/components/suggest-input/index.tsx`
(новый, общий комбобокс): дебаунс 300 мс, порог 3 символа, `ArrowDown`/`ArrowUp`/`Enter`/`Esc`,
`role="combobox"` + `aria-activedescendant`, гонка ответов отсекается билетом, ответ, пришедший после
ухода фокуса, список не открывает. Вид поля — та же плавающая метка, что у `modules/common/components/input`,
чтобы рядом с «Почтовым индексом» не было двух разных полей. Подключён в двух местах: поле «Город»
адресной формы (`address-autocomplete/manual-address-fields.tsx`) и поле города в листе ПВЗ.

**Свои маршруты для чтения СДЭК** — `apps/storefront/src/app/api/cdek/{cities,points}/route.ts` (новые)
плюс `fetchCdekCities`/`fetchCdekPoints` в `lib/util/cdek.ts`. Раньше лист ходил через server action:
Next исполняет действия страницы ПО ОДНОМУ, поэтому подсказка на каждые несколько нажатий вставала бы в
очередь за `setShippingMethod`. Ключ тенанта по-прежнему резолвится на сервере по `Host`
(`lib/config.ts`), в query его нет. Побочная польза — шов, который мокается в e2e.

**Переводы** — 4 ключа (`tabList`, `tabMap`, `mapEmpty`, `mapFailed`) в 36 каталогах, паритет проверен
скриптом из AGENTS.md: `checked 36 catalogs against 522 keys; mismatched: 0`.

## Находки, которые поймали проверки (а не глаз)

1. **Адресный лист стирал набранное.** Он пересевал поля из корзины при КАЖДОМ изменении `cart`, а
   `router.refresh()` на чекауте — это RSC-поход, который приезжает когда захочет. Набранный город
   через несколько секунд откатывался к сохранённому. Правило 19h. Теперь посев только на ОТКРЫТИИ
   листа (`checkout-address-sheet/index.tsx`). Поймал тест «manual entry survives».
2. **Список подсказок перехватывал клавиатуру.** Список открывается ПОД неподвижным курсором, и
   `mouseenter` срабатывает сам по себе — первая строка становилась активной, и первый `ArrowDown`
   уезжал на ВТОРУЮ. Живой замер: «Москв» + ArrowDown + Enter дало «Москворецкого Леспаркхоза», и
   дальше лист ПВЗ показывал 0 пунктов. Теперь подсветка только по `pointermove`.
3. **Выбранный пункт нельзя было сменить.** `RadioGroup` зовёт `onValueChange` только на СМЕНЕ
   значения, а карточка уже выбрана — повторный клик не делал ничего, и способа вернуться в лист не
   было (ключ перевода «Сменить пункт» лежал в 36 каталогах неиспользованным с i02). Добавлена ссылка
   «Сменить пункт» на выбранной карточке.
4. **Список подсказок упирался в нижний край листа** (лист — `overflow-y-auto`): из пяти городов было
   видно два с половиной. Теперь при открытии список подкручивается в видимую область.
5. **Мои e2e-файлы ломали `vitest`.** Переименованы в `*.pw.ts` по конвенции `tests/stands`.
   Осталось 3 таких же файла не моих (`tests/pdp/gallery.spec.ts`, `tests/pdp/layout.spec.ts`,
   `tests/ui-lab/toolchain.spec.ts` — из b17), их не трогал.

## Что НЕ сделано и почему

- **Подсказка улицы, дома и индекса.** Нужен платный сервис (DaData или Яндекс Геосаджест) — ключа нет
  ни в одном из четырёх мест выше, а выдумывать провайдера бриф запрещает. Сегодня подсказывается
  город (он же решает цену и список ПВЗ), индекс и улица набираются руками. Когда ключ появится:
  для DaData в витрине уже есть готовый провайдер (`address-autocomplete/providers/dadata.tsx`) и
  переключатель `hasAddressAutocomplete` — нужен только непустой `NEXT_PUBLIC_ADDRESS_AUTOCOMPLETE_PROVIDER_API_KEY`;
  общий комбобокс из этой задачи годится под любой источник (`fetchItems` — единственный шов).
- **Координаты из подсказки.** `/store/cdek/cities` в ветке префиксного поиска отдаёт `lat: null`,
  `lng: null` (у i02 так по построению: координаты есть только в точном поиске). Карта кадрируется по
  границам самих точек, так что на неё это не влияет.
- **Регион из подсказки не подставляется.** СДЭК отдаёт иерархию («городской округ Краснодар,
  Краснодарский край, Россия»), а зоны доставки магазина построены на канонических строках
  (`г Москва`, `Краснодарский край`, эндпоинт `/store/shipping-methods/regions`). Сопоставлять одно с
  другим — догадка, а неверный регион = неверная цена. Иерархия показана подсказкой, поле «Область»
  осталось за списком зон.
- **Карта для СОБСТВЕННЫХ пунктов магазина** (`checkout-pickup-point-sheet`, склады тенанта): у них в
  ответе `/store/pickup-points` нет координат вовсе, рисовать нечего. Нужен отдельный замер и,
  вероятно, поле координат у склада.
- **Деплой.** Задача не деплойная; на живой хост ничего не выкладывал.

## Экономия

**Что сделано скриптом вместо ручной работы:**

- `probe-ymaps.mjs` — 20 строк и один запуск браузера закрыли главную развилку задачи (годен ли наш
  ключ под suggest/geocode). Без него я бы писал провайдер подсказок на Яндексе и узнал про 403 на
  приёмке, потеряв час-полтора. Дешёвый решающий замер ПЕРЕД архитектурой — правило 18h.
- `i18n-i03.mjs` — 4 ключа × 36 каталогов = 144 строки перевода одним прогоном плюс проверка паритета
  скриптом из AGENTS.md. Руками это 36 правок и гарантированный расхождение ключей.
- `shots.mjs` — весь путь покупателя на двух разрешениях, 6 скриншотов и 9 замеров одним запуском;
  перезапускался 4 раза по ходу правок. Вручную это 8 проходов чекаута в браузере.
- Заглушка Яндекс-карты в e2e (`fixtures.ts`, 40 строк): набор не зависит ни от квоты ключа, ни от
  сети, и при этом проверяет то, что глазом не проверить — порядок координат `[lat, lng]`, состав
  переданных точек, `duration: 0` при reduced-motion, однократную загрузку скрипта.

**Что поймала машина, а не человек:**

- Гонку `router.refresh()` с набором в адресном листе (находка 1) — её видно только когда ответ
  приходит ПОСЛЕ ввода; глазами на быстром локальном стенде она не воспроизводится.
- Подсветку первой строки под неподвижным курсором (находка 2) — нашлась потому, что скрипт-приёмка
  печатает выбранное значение, а не «кликнул и поехали»; после неё я добавил в скрипт явный ассерт
  на «Москва» — второй прогон упал бы сразу.
- Невозможность сменить пункт (находка 3) — нашлась из проверки «скрипт карты грузится один раз»,
  которой понадобилось ЗАКРЫТЬ и снова ОТКРЫТЬ лист.
- Чужие критерии: `next build` подтвердил оба новых маршрута, `vitest` — что мои спеки собирались им
  по ошибке.

**Что автоматизировал бы дальше:** проверка «список подсказок не накрывает кнопку формы» сейчас живёт
одним ассертом в одном тесте — её стоит сделать общим хелпером для любого комбобокса в листах, потому
что каждый новый suggest-инпут в модалке принесёт этот же дефект. И порог «5 нажатий ≤ 2 запроса»
просится в общий тест-хелпер для дебаунса.
