# Новый магазин открывался с «Your connection is not private» — почему и что сделано

**Кто:** сессия-приёмщик МТ-деплоя. **Когда:** 2026-09-12, 03:50–04:10 WITA (2026-09-11 19:50–20:10 UTC).
**Заказ Ивана, дословно:** «нужно сделать все необходимое, чтобы данное сообщение никогда не появлялось».

## Что видел Иван

`https://testovyy-magazin.shipshift.dev` → `NET::ERR_CERT_AUTHORITY_INVALID`, а под кнопкой
«Advanced» нет ссылки «proceed» — только текст про HSTS. То есть обойти экран нельзя вообще.

## Диагноз, замерами, а не по памяти

| Замер | Результат |
| --- | --- |
| Сертификат для хоста без роутера (`SNI brand-new-check.shipshift.dev`) | `CN=TRAEFIK DEFAULT CERT`, самоподписанный, `notBefore=19:48:05 UTC` |
| Хост в `mt-tenants.yml` | появился в 19:47:54 UTC (`stat` файла) |
| LE-сертификат хоста | `acme.json` записан в 19:48 UTC, notBefore 18:49:32 (LE датирует на час назад) |
| Наши заголовки | `strict-transport-security` **не отдаётся** ни одним хостом |
| Зона `.dev` | `hstspreload.org/api/v2/status?domain=dev` → `"status": "preloaded"` |

Складывается в одну причину: **traefik просит сертификат у Let's Encrypt только ПОСЛЕ того, как
хост появился в ingress**, а до этого отвечает на TLS-рукопожатие своим самоподписанным
`TRAEFIK DEFAULT CERT`. Окно — около 90 секунд. Иван попал ровно в него: время выпуска
самоподписанного сертификата (19:48:05) — это отметка его собственного захода, traefik создаёт его
в момент первого рукопожатия, для которого нет настоящего.

Кнопка «proceed» отсутствует не из-за нашего кода: **вся зона `.dev` стоит в HSTS-preload списке
Chrome**, там click-through запрещён браузером. Поэтому для владельца магазина это не «предупреждение,
которое можно пропустить», а полностью закрытая дверь на полторы минуты.

Второй счётчик, который тикал в ту же сторону: каждый новый магазин съедал один сертификат из
недельного лимита LE на зону (50 на registered domain). На 2026-09-11 израсходовано 10 —
`shipshift.dev`, `panel`, `initech`, `globex`, `acme`, `api.dev.cherkashina`, `dev.cherkashina`,
`stores`, `nochlavka`, `testovyy-magazin`. На 41-м магазине за неделю выпуск начал бы падать, и
сообщение стало бы не окном в 90 секунд, а постоянным состоянием.

## Что сделано

1. **Wildcard `*.shipshift.dev`, выпущенный по DNS-01 через Cloudflare** (`lego 5.4.1` в
   одноразовом контейнере, токен `CLOUDFLARE_CF_ADMIN_TOKEN` в `/root/.lego-cf.env`, 600).
   HTTP-01 wildcard не умеет — поэтому DNS-01.
   Ловушка, стоившая первой попытки: собственный рекурсивный резолвер хоста (213.136.95.10) не
   возвращал только что записанный TXT, и проверка распространения падала по таймауту. Лечится
   `--dns.resolvers 1.1.1.1:53 --dns.resolvers 8.8.8.8:53`.
2. **Сертификат отдан traefik через file-provider** — `/data/coolify/proxy/dynamic/mt-wildcard-tls.yml`
   (канон в репозитории: `deploy/mt/traefik-wildcard-tls.yml`). Это ДИНАМИЧЕСКАЯ конфигурация:
   статические аргументы `coolify-proxy` не тронуты, прокси не перезапускался, чужие приложения на
   этом же прокси не задеты.
3. **`tenant-ingress-sync.sh` больше не просит per-host certResolver** для хостов под
   `TENANT_BASE_DOMAINS` — им пишется `tls: {}`, и сертификат берётся из хранилища. Свои домены
   тенантов (`custombot.space`) резолвер сохраняют: wildcard их не покрывает. Новая функция
   `covered_by_wildcard` строго проверяет ОДНУ метку: `shop.shipshift.dev` да, `a.b.shipshift.dev` нет.
4. **`INGRESS_SYNC_INTERVAL` 15 → 5 с** — остаточное окно теперь не «нет сертификата», а «роутера
   ещё нет» (traefik отвечает 404 по валидному TLS), и оно втрое короче.
5. **Продление** — `deploy/scripts/renew-wildcard-cert.sh` + cron `20 4 * * *` на хосте, лог
   `/var/log/wildcard-renew.log`. Срок решает сам скрипт (`openssl -checkend`, 30 дней), а не lego:
   ежедневный безусловный перевыпуск сжёг бы лимит дубликатов (5 в неделю на одинаковый набор имён)
   за пять дней. После продления скрипт переписывает строку `# renewed:` в yml — traefik следит за
   ФАЙЛОМ конфигурации, а не за файлами сертификатов, на которые тот ссылается.

## Приёмка (всё на живом проде)

| Проверка | До | После |
| --- | --- | --- |
| SNI несуществующего хоста | `CN=TRAEFIK DEFAULT CERT` | `CN=*.shipshift.dev`, issuer Let's Encrypt |
| Роутер с certResolver, пока ACME ещё не ответил | самоподписанный | `CN=*.shipshift.dev` (6 замеров подряд, probe-роутер снят) |
| `acme/globex/initech/nochlavka/testovyy-magazin` | свои сертификаты | свои же, `ssl_verify=0`, коды 302 не изменились |
| `panel`, `shiftship.dev` | свои сертификаты | свои же, 200 / 307 |
| `mt-tenants.yml` | 11 роутеров с certResolver | 5 × `tls: {}` (тенанты) + 6 certResolver (свои домены) |

Важное следствие третьего замера: сообщение не вернётся, даже если кто-то раскатает старую версию
`tenant-ingress-sync.sh` — wildcard из хранилища перекрывает окно ACME сам по себе.

## Что осталось открытым

- Свои домены тенантов (`custombot.space` и подобные) по-прежнему получают сертификат через HTTP-01
  и имеют то же окно. Там click-through браузер разрешает (зона не `.dev`), но для владельца это
  всё равно страшный экран. Решение — либо тот же on-demand подход, либо предупреждение в панели
  «адрес станет доступен через ~2 минуты».
- Окно «роутера ещё нет» (до 5 с) отдаёт traefik-404. Если захотим — страница «магазин готовится».
- `https://shipshift.dev/` (apex платформы) отдаёт `Cannot GET /` от Express — отдельный дефект,
  зафиксирован в приёмке волны 1.

## Откат

Удалить `/data/coolify/proxy/dynamic/mt-wildcard-tls.yml` (traefik перечитает за секунду), вернуть
старый `tenant-ingress-sync.sh`, снять строку cron. Сертификаты в `acme.json` не трогались.
