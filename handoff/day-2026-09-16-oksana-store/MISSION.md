## Как организована работа (спека диспетчера, s8)
- Очередь задач: `tasks.json` (порядок, зависимости, ветки, модель, усилие, промпты в `prompts/`). Планировщик: `dispatcher.mjs` — слоты по «полосам» (build / data / accept / deploy / qa), задача запускается, как только все её зависимости смержены, а в полосе есть место.
- Исполнитель build-задачи = Superset workspace с агентом (`superset ws create --agent claude --model … --effort … --prompt …`) → ветка задачи → `gh pr create --base dev` → приёмщик (`claude -p`, промпт `prompts/_acceptor.md`) проверяет и мержит на GitHub → deploy-задача выкатывает dev на живой хост → qa-задача проверяет живой магазин браузером и заводит найденные дефекты как новые задачи.
- UI: `node ui/server.mjs` → http://localhost:5390 — таблица задач, редактор промпта, кнопка RUN (создаёт ветку + workspace + агента), пауза/возобновление, ссылки на PR/логи/отчёт.
- Отчёт для Ивана: `REPORT.md` (перегенерируется каждую минуту) + вкладка «Отчёт» в UI.
- Память планировщика: `state.json`, журнал `logs/dispatcher.jsonl`. Остановка: файл `STOP` (пауза) или `DONE`.
