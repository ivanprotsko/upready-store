## 1. Принципы

1. **Один канал.** Иван пишет только в страницу «Оператор» UI (тот же сервер, что очередь дня,
   http://localhost:5390) и читает ответы там же. В Fable и Opus он не пишет. Сообщения штаба Ивану
   идут в ту же ленту записью вида `notice`, а не в чат сессии.
2. **Вверх только при провале, и провал меряет скрипт.** Каждый уровень (скрипт, haiku, sonnet, opus,
   fable) отдаёт ответ по одной схеме, и один и тот же **гейт** (§5) решает, ответ это или нет.
   Слово модели «готово» гейтом не является.
3. **Старт не всегда снизу.** Уровень старта задаёт **тип записи** (§4): вопрос о факте начинает со
   скриптов, вопрос о решении — сразу с opus, баг на живом — с sonnet-воспроизведения. Так низшие
   уровни не тратятся там, где заведомо не ответят.
4. **Без резидентного Opus.** Каждый уровень — `claude -p` без состояния с **пакетом контекста**,
   собранным скриптом (запись + найденные пассажи + вердикт нижнего уровня). Пакет один и тот же,
   выше добавляется только «почему не вышло ниже». Резидентная сессия с `/compact` после каждой
   задачи стоит дороже: сжатие — это отдельный дорогой ход, а состояние между задачами не нужно, оно
   лежит в пакете. Инициализация `claude -p` — общий префикс системного промпта, то есть в основном
   чтение кэша; замер — по полю `usage` JSON-ответа (ledger, §8).
5. **Единственный резидент — Fable** (эта сессия): она и так стоит сторожем на очереди дня и получает
   события Monitor. Эскалация к ней — строка в `intake/escalations.log`, как сейчас пачки.
6. **Скрипт, тест, схема — раньше модели** (правило 47). Разбор путей, дубли, поиск по корпусу,
   типовые документы (статус, «где результат»), живые пробы, гейт, журнал, рендер — скрипты с тестами.
   Модели — только там, где нужно суждение: разбить свободный текст, сложить ответ из пассажей,
   воспроизвести баг, написать промпт воркера, принять решение.

## 2. Схема (нотация Ивана, с поправками)

```
1 Иван → UI /operator (текст)
2 разбор: скрипт (валидация, пути → refs/refsMissing, дубли, конкуренты)
          + haiku `claude -p --json-schema` (разбить на записи, kind, area, ivan дословно)
3 хранилище: operator.db (SQLite) + prompts/<id>.md + records
4 маршрут по kind (§4):
   fact / where / status / live ──► 4a скрипты: ask.mjs (FTS-пассажи), типовые документы, live-пробы
                                        │ гейт зелёный ──► 4.1 документ answers/<rid>.md ──► 5 UI
                                        │ гейт красный
                                        ▼
                                    4.1.1 haiku: сложить ответ из пассажей (схема + источники) ──► гейт
                                        ▼ красный
                                    4.1.2 sonnet: ищет сам (grep, qa.mjs, чтение файлов, ≤12 ходов) ──► гейт
                                        ▼ красный
                                    4.1.3 opus: пакет контекста, ответ/триаж ──► гейт
                                        ▼ красный
                                    4.2   fable (Monitor на escalations.log) ──► документ | «не найдено, пробовали: …» ──► 5 UI
   decision / why-not ────────────► старт с 4.1.3 (opus), ниже не тратим
   bug (live:true) ───────────────► 4b sonnet: воспроизвести (curl / Playwright-кадр), черновик goal+acceptance
                                    ──► 5 UI «в очередь» (Иван) ──► dispatcher add-task; ответ = отчёт воркера при done
   task ─────────────────────────► 4c sonnet: черновик goal+acceptance+refs; opus: промпт воркера по шаблону
                                    ──► 5 UI «в очередь» (Иван)
   remark / order ───────────────► запись; штаб читает пачкой (как сейчас, intake.mjs batch)
   approval («делай», «ок», «не то») ► скрипт связывает с ожидающей записью и выполняет действие
```

Отличия от схемы Ивана: (а) haiku стоит в двух местах — разбор (шаг 2) и первая попытка сложить
ответ из уже найденных пассажей (4.1.1), sonnet остаётся для самостоятельного поиска; (б) «success?»
на шаге 4 — не «скрипт что-то нашёл», а гейт §5, одинаковый для всех уровней; (в) старт по типу
записи; (г) opus без состояния; (д) провал Fable — документ «не найдено» в ту же ленту, а не сообщение
в sonnet: sonnet-сессии как резидента нет вовсе, «оператор» = UI + `operator.mjs`.

## 5. Гейт (один для всех уровней, проверяет скрипт)

Схема ответа уровня (`answer.schema.json`, для `claude -p --json-schema` — флаг есть, замерено в
`claude --help`):

```json
{ "answered": true, "doc_md": "…", "sources": [{ "path": "…", "quote": "…", "date": "…" }],
  "confidence": 0.0, "live": [{ "cmd": "…", "result": "…", "ts": "…" }], "not_found": ["…"] }
```

Зелёный, если ВСЕ условия выполнены:

1. `sources.length ≥ 1`, каждый `path` существует на диске и лежит внутри корпуса;
2. каждый `quote` найден в файле дословно (`grep -F`), не короче 20 знаков;
3. `doc_md` ≥ 200 знаков и не содержит путей, которых нет в `sources`;
4. для kind=live — в `live` есть замер с `ts` этого прогона;
5. для kind=decision — есть раздел «Рекомендация» и хотя бы один «Против».

Красный гейт печатает причины; они уходят в пакет уровня выше как «ниже не вышло: …». Ответ,
прошедший гейт, всё равно несёт плашку уровня и кнопку «не то» — Иван одним нажатием отправляет запись
на уровень выше, а `verdict_ivan=wrong` — метрика для ledger.

Это правило 17a, встроенное в код: ответ без проверяемого источника ответом не является.

|---|---|---|

| `intake/levels.mjs` | запуск уровня: `claude -p --model <haiku|sonnet|opus> --json-schema answer.schema.json --allowedTools …` с пакетом контекста; пишет `answers`, `usage` | сухой запуск с подменой `claude` на заглушку |

| `ui/server.mjs` (есть) + `index.html` | вкладка «Оператор»: `POST /api/op/prompt`, `GET /api/op/thread`, `GET /api/op/answer?id`, `POST /api/op/verdict {ok|wrong|queue}`; рендер md → HTML | маршруты на фикстурах |

Уровень sonnet работает с ограничением ходов и списком инструментов только на чтение (`Read`, `Grep`,
`Bash` с белым списком: `grep`, `ls`, `node …/qa.mjs search`, `curl -sI`); писать он может только в
`intake/answers/`. Уровень opus получает тот же список плюс Playwright для кадров. Никакой уровень ниже
Fable не пишет в `tasks.json`, `state.json`, не запускает `run.sh`, не коммитит (как в PROMPT.md v1).

## 7. UI: страница «Оператор»

- Сверху поле ввода (как чат). Ниже лента: **мой промпт** (дословно, время) → под ним карточки записей
  (kind, area, заголовок) → под каждой документ ответа (рендер md), плашка уровня и времени, источники
  ссылками на `/api/file?f=…`, кнопки «ок», «не то → выше», для bug/task — «в очередь», для decision —
  «принять вариант N».
- Пока ответа нет — строка «ищет: скрипт → haiku → …» с текущим уровнем и временем ожидания.
- Записи штаба (`notice`) — в той же ленте, помечены «штаб».
- Ничего не рендерится из `.private` и `.env`: только ссылка на файл, который Иван откроет сам.

## 9. Риски и что не делать

- **Галлюцинация нижнего уровня.** Лечится гейтом §5 (источник + дословная цитата на диске) и кнопкой
  «не то». Ответ без источника не показывается как ответ.
- **Устаревшая запись.** Значения, которые крутятся без записи в канон (ключи, адреса на стенде,
  переменные окружения), в документе помечаются «по записи от <дата>», а kind=live меряет заново.
- **Плохой разбор промпта.** haiku может склеить два вопроса или потерять ссылку «тот вопрос про X».
  Метрика — правки Ивана в карточке; при доле выше 1 из 5 разбор переводится на sonnet (одна строка в
  `ROUTES`).
- **Не читать стенограммы целиком** — ни на одном уровне; только `grep -F`.
- **Не держать резидентный Opus/Sonnet.** Резидент один — Fable, и тот через Monitor.
- **Задачи и баги не «отвечаются»** — они готовятся и ждут кнопки Ивана (правило 22j: задачи заводит
  Иван; кнопка «в очередь» и есть его акт).
- **Секреты** не попадают ни в индекс, ни в документы, ни в пакеты уровней — только имена переменных.
