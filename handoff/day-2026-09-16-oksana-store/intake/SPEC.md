К примеру когда собралось некоторое количество схожих по области работы задач или другим характеристикам». 20:34: «Делай».

## Роли
- **Входящая сессия** (sonnet, промпт `PROMPT.md`) — принимает сообщения Ивана, приводит к стандарту, проверяет пути на диске, пишет запись через `node intake.mjs add`. НЕ заводит задачи в tasks.json, НЕ запускает воркеров, НЕ правит код продукта, НЕ коммитит.
- **Скрипт** `intake.mjs` — валидация, проверка путей, дедупликация против inbox и tasks.json, подбор аналога у конкурентов по реестру r03, детерминированная склейка пачек, журнал `batches.log`.
- **Главная сессия** (Fable, штаб дня) — сторож Monitor читает `batches.log`, штаб разбирает пачку: в очередь дня (`add-task`), ответ Ивану, или `drop`. После разбора `take <batchId>`.

## Запись (inbox.json)
| поле | обяз. | что |
|---|---|---|
| kind | да | task · bug · remark · question |
| area | да | panel · checkout · storefront · marketplaces · integrations · deploy · content · engine · other |
| title | да | ≥8 знаков, одно предложение, без «исправить» в начале |
| ivan | да | дословный текст Ивана (цитата, не пересказ) |
| goal | кроме question | что должно стать правдой |
| acceptance | кроме question | измеримый критерий (число, адрес, кадр) |
| priority | нет | 1 срочно · 2 обычно (по умолчанию) · 3 потом |
| live | нет | true, если дефект виден на живом хосте (cherkashino.shipshift.dev, panel-store.upready.dev) |
| refs | нет | пути от корня репозитория; скрипт проверяет `existsSync`, не найденные уходят в `refsMissing` и помечаются «не верить» |
| competitors | авто | совпадение с `artifacts/research/2026-09-16-store-templates-functionality/features.json` (InSales/Tilda: сколько шаблонов); нет совпадения — «проверить вручную» |
| dup | авто | id похожих записей (Жаккар по словам заголовка ≥ 0,5) в inbox и tasks.json |
| notes | нет | что входящая сессия проверила сама (команда + результат), чего не нашла |

Статусы: `new` → `batched` (в пачке) → `taken` (штаб разобрал) · `dropped`.

## Склейка (planBatches, детерминирована, покрыта `intake.test.mjs`)
1. `question`, `bug` с `live:true` или `urgent:true` — пачка из ОДНОЙ записи немедленно (Иван не ждёт ответа из-за «пачка маленькая»).
2. Иначе группа = одна `area`, только готовые записи (goal и acceptance заполнены), порядок priority → ts.
3. Пачка формируется, когда готовых ≥ 3 ИЛИ самая старая готовая ждёт ≥ 120 мин; берётся до 7 записей.
4. Пачка = `batches/<id>.md` + строка в `batches.log`; записи → `batched`.
5. Сторож главной сессии: `while true; do node intake.mjs batch --auto; sleep 60; done` — каждая новая строка = событие в чат штаба.
