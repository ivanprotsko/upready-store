# Матрица разрывов: upready-store против InSales «Комбо»

Источники: `insales-combo-features.md` (169 функций конкурента, id из §4), `upready-store-capabilities.md`
(инвентарь `dev` на 2026-09-15), `telegram-digest.md` §3/§8 (что просил реальный клиент — Оксана Черкашина),
`tasks.json` (очередь дня 2026-09-16). Сеть не трогалась — работа только по файлам.

## Сводка

Из 169 функций InSales «Комбо»: **есть** — 11, **частично** — 33, **нет** — 106, **не применимо** (относится
к бизнесу самого insales как SaaS-провайдера — реферальная программа, магазин приложений, поддержка/обучение
клиентов, услуги миграции/онбординга — а не к магазину) — 19.

Три разрыва, которые больнее всего бьют по реальному магазину Оксаны:

1. **Приём денег.** Ни ЮKassa/Robokassa, ни онлайн-кассы (54-ФЗ) в коде нет — только ручной провайдер без
   списания денег. Клиент уже подключил тестовый режим Robokassa (#463583), боевой запуск ждёт задачу
   `t03-tenant-secrets-robokassa`. Без онлайн-кассы магазин юридически не может принимать деньги легально —
   строки не назначены ни одной задаче дня.
2. **Маркетплейсы (WB/Ozon/Яндекс Маркет/Avito).** У InSales «Комбо» это ядро линейки — единая лента заказов,
   единый остаток, синхронизация статусов. У нас нет ни одной строки кода под это; клиент явно просила
   «единую панель заказов WB + Ozon + магазин» (#468851, #472253) — задачи дня на это нет.
3. **Доставка по-настоящему.** Только две ручные плоские опции на тенанта; расчёта по весу/зонам, реальных
   служб (СДЭК/Почта России/Boxberry) и трекинга нет. Клиентский сценарий «цена за кг по зонам + ручной
   трек-номер» (#463839) частично закрывает `t04-shipping-tariffs`.

Только строки `критично` (их в таблице 18; наивный разбор по `|` теряет три ряда, где труба стоит
