## 1. Исходная идея Ивана (S1, 2026-09-12 07:41Z и 08:18Z, Иван)

Формат планирования — три типа файлов:
- **Файл задачи** (md/json): «`tokens_min` / `tokens_max` — прогноз расхода токенов», «`model` — подходящая модель», «`keywords` — ключевые слова … ускорят поиск задач при перераспределении между группами».
- **Файл группы**: «индекс входящих задач … суммарный прогноз токенов: от и до … список моделей, необходимых для выполнения перечисленных задач».
- **Файл промпта агента**: «стартовый промпт … список назначенных ему групп задач».
- Правила группировки: «Группу, максимальный контекст которой не превышает 150k токенов, выполняем в рамках одной сессии … добавить близкие по смыслу одиночные задачи … суммарный объём не превысит 180k». Группа из одной задачи допустима, в т.ч. «задачу выполняет модель, под которую нет других задач».
- Этапы: планирование (файлы ссылаются путями) → «Сборка. … скрипты собирают финальные файлы … читать другие файлы агенту не потребуется».

Три схемы подачи (вопрос Ивана «какая схема подачи задач эффективнее и экономнее?»):
1. агент сразу получает все задачи со стартовым промптом;
2. получает ссылки и читает следующую после предыдущей;
3. «Агенту на старте назначается только одна задача. Выполнив её, он ставит отметку … скрипт отправляет в его сессию описание следующей задачи».

## 6. Поворот схемы: от stream-json-воркеров к слотам Superset (S1, 11:39Z и 12:09Z, ассистент)

«Исходная схема 3 из твоего конспекта: N долгоживущих процессов на stream-json, задачи подаются в тот же процесс одна за другой, контекст переносится между задачами, диспетчер выбирает свободный воркер с подходящей группой. Текущая схема: долгоживущий слот, а процесс живёт одну задачу». Причины: зачёт PR требует workspace с агентом на ветку (смена ветки в worktree запрещена 21e); depth при ≤50 файлов/день не нуждается в долгоживущих процессах; не нужен недокументированный inbox. «Что сохранилось: ноль простоя между задачами, фиксированная параллельность, запрет сабагентов, переключение подписки. Что потерялось: перенос контекста между родственными задачами. Компенсация … группа = один PR … промпт несёт указатели на память и спеки».
