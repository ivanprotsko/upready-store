## Как выполнялся импорт — и одна честная оговорка про источник

Скрипт `apps/backend/src/scripts/import-cherkashina-reviews.ts` (уже собранный в живом образе как
`/app/src/scripts/import-cherkashina-reviews.js`) читает три источника: два JSON-файла старого
магазина, реестр соответствий миграции и — опционально — базу старого магазина как слой правок
владелицы поверх файлов.

Запускать его пришлось **внутри контейнера `mt-backend`**: только там есть живая база `medusa_mt`.
Из контейнера не видно базу старого магазина (`medusa_chrxn` живёт на этом ноутбуке,
`127.0.0.1:5433`), поэтому слой правок был **замерен заранее, локально**
(`src/merge-overlay.mjs` → `data/overlay-stats.json`):

```
translation_rows: 664   (ru: author 166 + text 166, en: author 166 + text 166)
ru: 166 отзывов, 166 с записью в слое, differs = 0
en: 166 отзывов, 166 с записью в слое, differs = 0
```

**Ни одна строка слоя не отличается от файла** — правки владелицы в старой админке либо не делались,
либо уже вошли в файлы. Слитые файлы после наложения слоя побайтово (по структуре JSON) равны
исходным — проверено сравнением. Поэтому запуск без `REVIEWS_SOURCE_DB` даёт ровно те же строки, и
предупреждение скрипта «author and text come from the JSON files alone» в этом прогоне ничего не
меняет по существу.

Файлы, отданные контейнеру (md5 совпал на всех трёх этажах — ноутбук, хост, контейнер):

```
/app/reviews-import-b05/reviews-data.json               f42c02fee97f2b3a66a9b63a9d9bc17f
/app/reviews-import-b05/reviews-data.en.json            102419547d11c51cd378d810914f8acc
/app/reviews-import-b05/02-mapping-registry-live.json   a1e5800d6b172cdbfceeba1534bffc9d
```

Реестр взят **живой** (`artifacts/x01-tenant-live-import/02-mapping-registry-live.json`, 38 товарных
строк с `target_id`) — не превью-вариант: id товаров на живом хосте свои.

Команда боевого прогона:

```
docker exec -e REVIEWS_DATA_DIR=/app/reviews-import-b05 \
  -e REVIEWS_MAPPING_REGISTRY=/app/reviews-import-b05/02-mapping-registry-live.json \
  -e REVIEWS_TENANT_HANDLE=cherkashino \
  mt-backend npx medusa exec ./src/scripts/import-cherkashina-reviews.js allow-unmapped
```

`allow-unmapped` передан **после** прочтения списка непривязанных из сухого прогона — это то, для
чего флаг и сделан: без него скрипт выходит с кодом 3, чтобы список нельзя было проскочить не глядя.
