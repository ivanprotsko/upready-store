# Архив заказов и покупателей старого магазина

Этот архив передаётся потому, что история заказов и карточки покупателей **не переносятся** между
платформами: нет зафиксированного согласия на передачу персональных данных другому оператору, а
пересоздание заказов на новой площадке подделало бы их историю. Вместо переноса — выгрузка.

## Откуда данные и на какой момент

- Источник: база старого магазина (Medusa 2.17.2, PostgreSQL 16), `medusa_chrxn`.
- Снимок снят: **2026-09-15 03:37 WITA**. Данные читались только на чтение, в базу ничего не записывалось.
- Заказы в базе — с **2025-07-27 по 2026-09-01**.
- Часовой пояс всех дат в файлах — **WITA (UTC+8)**, тот же, что на рабочей машине.

## Что в файлах

| Файл | Строк | Что это |
|---|---|---|
| `orders.csv` | 88 | по одной строке на заказ |
| `order-items.csv` | 135 | по одной строке на позицию заказа, связь по колонке «Номер заказа» |
| `customers.csv` | 46 | по одной строке на покупателя |

Состав заказа есть в обоих видах: в `orders.csv` одной читаемой колонкой («SKU — товар × кол-во × цена»,
позиции разделены знаком `|`), а в `order-items.csv` — построчно, чтобы можно было считать по товарам.

### Как открыть

Файлы в кодировке UTF-8 с BOM, разделитель — **точка с запятой**, десятичный разделитель — **запятая**.
Excel и LibreOffice открывают их двойным щелчком, кириллица не ломается. Номера заказов и телефоны
записаны как текст (в формате `="..."`), чтобы таблица не съела ведущий плюс или ноль.

## Колонки `orders.csv`

| Колонка | Значение |
|---|---|
| Номер заказа | номер, который видел покупатель (`display_id`) |
| Дата (WITA) | когда заказ создан |
| Статус заказа | «в работе» / «завершён» / «отменён» |
| Статус оплаты | вычислен по факту оплаты: «оплачен», «оплачен частично», «не оплачен», «нечего оплачивать» (итог заказа = 0) |
| Статус отгрузки | «не отгружен» / «собран» / «отправлен» / «доставлен» |
| Покупатель | имя из адреса доставки заказа |
| E-mail | почта, указанная в заказе |
| Телефон | телефон из адреса доставки |
| Адрес доставки | индекс, страна, регион, город, улица — одной строкой |
| Способ доставки | название выбранного способа доставки |
| Валюта | RUB или USD |
| Сумма товаров | сумма позиций без доставки |
| Доставка | стоимость доставки |
| Скидка | скидка по заказу |
| Итого | итоговая сумма заказа |
| Оплачено | сколько по этому заказу фактически поступило |
| Позиций, шт | суммарное количество единиц товара |
| Состав заказа | позиции одной строкой |

## Колонки `customers.csv`

Покупатель, E-mail, Телефон, Есть личный кабинет, Дата регистрации (WITA), Заказов шт, Валюты,
Потрачено RUB, Потрачено USD, Первый заказ, Последний заказ, Последний адрес доставки.
«Потрачено» — сумма итогов заказов покупателя, отдельно по каждой валюте (складывать рубли с долларами нельзя).
«Последний адрес доставки» — адрес из самого свежего заказа этого покупателя.

## Проверка сходимости

- Заказов в файле — 88, в базе — 88. Покупателей в файле — 46, в базе — 46. Совпадает с тем, что было
  зафиксировано при разборе магазина 2026-09-12.
- Сумма колонки «Итого» по 77 рублёвым заказам: **694 211 ₽** — ровно столько же даёт прямой запрос-агрегат
  к базе (694 211). По 11 долларовым заказам: **7 264,11 $** против 7 264,11 в базе.
- Оплачено по рублёвым заказам: 282 912 ₽ (столько же в базе).
- В каждой из 88 строк «Итого» = «Сумма товаров» + «Доставка» − «Скидка»; расхождений — 0.
- Единиц товара в `orders.csv` — 174, в базе — 174; строк в `order-items.csv` — 135, в базе — 135.

Три заказа сверены с базой поле за полем (по 10 полей каждый, включая контрольную сумму пары e-mail+телефон),
расхождений нет:

|---|---|---|---|
| № 100 | 44 544 ₽ | 8 | completed |
| № 21 | 12 903 ₽ | 5 | pending |

## Что стоит знать о данных

Пустая ячейка означает, что значения в базе нет. Пустоту не заменяли нулём или прочерком — «нет данных» и
«ноль» это разные вещи.

- **Телефон не указан в 39 заказах из 88** и у 29 покупателей из 46 — в старом магазине это поле не было
  обязательным.
- **Способ доставки пуст в 33 заказах из 88**: доставка в них не оформлялась через магазин, стоимость
  доставки в таких заказах — 0.
- **Имя и адрес отсутствуют в 6 заказах из 88** — в них не заполнен адрес доставки.
- **Заказ № 19 не содержит ни одной позиции** и его итог равен нулю. Это заказ, брошенный на полпути;
  он оставлен в архиве как есть, а не вычищен, чтобы номера не разъезжались.
- **26 покупателей из 46 не сделали ни одного заказа** — это регистрации без покупки. У них пусты колонки
  про заказы и адрес.
- **Скидок в архиве нет**: ни к одному заказу и ни к одной позиции скидка в базе не применена, поэтому
  колонка «Скидка» везде 0. Налоговых строк в заказах тоже нет.
- **Отгрузка зафиксирована только у одного заказа** (№ 9, отправлен 2026-07-01). У остальных 87 в базе нет
  записи об отгрузке — статус «не отгружен» означает именно отсутствие записи, а не то, что товар не уехал:
  отправки могли не отмечаться в магазине.
- **Две валюты**: 77 заказов в рублях (с 2025-07-27 по 2026-09-01) и 11 в долларах (все — с 2026-05-21 по
  2026-07-02). Суммы по валютам считаются отдельно и в один столбец не складываются.
- **Нумерация заказов с пропусками**: номера идут от 1 до 117, а заказов 88 — 29 номеров в базе отсутствуют
  (незавершённые оформления, которые до заказа не дошли).
- Статусы оплаты и отгрузки в Medusa не хранятся готовым полем, а выводятся из сумм платежей и отметок об
  отправке; в этом архиве они посчитаны по тем же правилам и переведены на русский.

## Персональные данные

В файлах есть имена, телефоны, адреса и почтовые адреса покупателей. Это персональные данные: архив не
выкладывается в открытый доступ, не публикуется и не заливается в новый магазин; он передаётся владелице
магазина как её собственная выгрузка.
