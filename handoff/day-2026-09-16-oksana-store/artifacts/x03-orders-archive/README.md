# Архив заказов и покупателей старого магазина

Этот архив передаётся потому, что история заказов и карточки покупателей **не переносятся** между
платформами: нет зафиксированного согласия на передачу персональных данных другому оператору, а
пересоздание заказов на новой площадке подделало бы их историю. Вместо переноса — выгрузка.

## Откуда данные и на какой момент

- Источник: база старого магазина (Medusa 2.17.2, PostgreSQL 16), `medusa_chrxn`, чтение напрямую.
- Снимок снят: **2026-09-15 03:49 WITA**. Работа велась только на чтение; в базу не записано ни строки.
- Заказы в базе — с **2025-07-27 по 2026-09-01**.
- Часовой пояс всех дат в файлах — **WITA (UTC+8)**.
- Выгрузка воспроизводима: запросы лежат рядом в `orders.sql`, `items.sql`, `customers.sql`,
  сборка — `export.py`, сверка с базой — `verify.py` (её вывод: `verification.log`).

## Что в файлах

| Файл | Строк | Что это |
|---|---|---|
| `orders.csv` | 88 | по одной строке на заказ |
| `order-items.csv` | 135 | по одной строке на позицию заказа, связь по колонке «Номер заказа» |
| `customers.csv` | 46 | по одной строке на покупателя |

Состав заказа есть в обоих видах: в `orders.csv` одной читаемой колонкой («SKU — товар × кол-во × цена»,
позиции разделены знаком `|`), а в `order-items.csv` — построчно, чтобы можно было считать по товарам.

### Как открыть

Файлы в кодировке UTF-8 с BOM, разделитель — **точка с запятой**, десятичный разделитель — **запятая**.
Excel и LibreOffice открывают их двойным щелчком, кириллица не ломается. Номера заказов, SKU и телефоны
записаны как текст (в формате `="..."`), чтобы таблица не съела ведущий плюс или ноль.

## ⚠️ Главное, что нужно знать до того, как смотреть суммы

**Из 88 заказов 77 — служебные: это наши собственные тестовые заказы, накопившиеся в магазине за время
его разработки, а не покупки клиентов.** То же с покупателями: из 46 карточек служебных — 40.

Признак служебной записи — почтовый адрес: либо технический домен, который не существует в интернете
(`*.local`, `*.test`, `example.com`, `*.invalid`) или принадлежит нам (`upready.dev`, `ivanprotsko.com`),
либо тестовый ящик на домене самого магазина (`test@`, `demo@`, `selfheal-…`, `p1-…`–`p7-…`).
В `orders.csv` и `customers.csv` для этого добавлена последняя колонка **«Служебная запись»**: у служебных
там стоит пометка, у остальных ячейка пуста. Отфильтруйте по ней, прежде чем считать что-либо про выручку.

| | Заказов | Итого RUB | Оплачено RUB | Итого USD | Оплачено USD | Даты |
|---|---|---|---|---|---|---|
| Служебные | 77 | 684 915 | 273 616 | 7 193,95 | 41,30 | 2025-07-27 … 2026-09-01 |
| Остальные | 11 | 9 296 | 9 296 | 70,16 | 70,16 | 2026-07-02 … 2026-08-05 |
| **Всего** | **88** | **694 211** | **282 912** | **7 264,11** | **111,46** | |

Итог 694 211 ₽ по всей таблице — это **не выручка магазина**; подавляющая часть суммы приходится на
тестовые заказы. Из 6 неслужебных карточек покупателей заказы делали 4.

Оговорка о самом признаке: он определён по почтовому адресу, и это эвристика, а не запись в базе —
отдельного поля «тестовый заказ» в магазине не было. Девять «остальных» заказов оформлены на адресах
домена самого магазина (`@chrxn.store`) и, судя по домену, тоже могут быть внутренними. Ни одна строка
из архива не удалена: помечены, но оставлены все, чтобы номера заказов не разъезжались.

## Колонки `orders.csv`

| Колонка | Значение |
|---|---|
| Номер заказа | номер, который видел покупатель (`display_id`) |
| Дата (WITA) | когда заказ создан |
| Статус заказа | «в работе» / «завершён» / «отменён» |
| Статус оплаты | вычислен по факту оплаты: «оплачен», «оплачен частично», «не оплачен», «нечего оплачивать» (итог заказа = 0) |
| Статус отгрузки | «не отгружен» / «собран» / «отправлен» / «доставлен» |
| Покупатель | имя из адреса доставки заказа |
| E-mail | почта, указанная в заказе |
| Телефон | телефон из адреса доставки |
| Адрес доставки | индекс, страна, регион, город, улица — одной строкой |
| Способ доставки | название выбранного способа доставки |
| Валюта | RUB или USD |
| Сумма товаров | сумма позиций без доставки |
| Доставка | стоимость доставки |
| Скидка | скидка по заказу |
| Итого | итоговая сумма заказа |
| Оплачено | сколько по этому заказу фактически поступило |
| Позиций, шт | суммарное **количество единиц** товара (не число строк в заказе) |
| Состав заказа | позиции одной строкой |
| Служебная запись | пометка тестового заказа; у обычных пусто (см. раздел выше) |

## Колонки `customers.csv`

Покупатель, E-mail, Телефон, Есть личный кабинет, Дата регистрации (WITA), Заказов шт, Валюты,
Потрачено RUB, Потрачено USD, Первый заказ, Последний заказ, Последний адрес доставки, Служебная запись.

- «Потрачено» — сумма итогов заказов покупателя, отдельно по каждой валюте (складывать рубли с долларами нельзя).
- «Телефон» берётся из карточки покупателя, а если там пусто — из адреса его последнего заказа.
- «Последний адрес доставки» — адрес из самого свежего заказа этого покупателя.
- У покупателей без заказов «Заказов, шт» и «Потрачено» равны **нулю** (это измеренный ноль, а не пропуск),
  а «Валюты», «Первый заказ», «Последний заказ» и адрес — пусты.

## Проверка сходимости

Сверка сделана скриптом `verify.py`: он перечитывает готовые CSV **с диска** и сравнивает их с прямыми
запросами к базе. Полный вывод — в `verification.log`, все 22 проверки прошли.

- Заказов в файле — 88, в базе — 88. Покупателей в файле — 46, в базе — 46. Позиций — 135 и 135.
  Совпадает с тем, что зафиксировано при разборе магазина 2026-09-12 (88 заказов, 46 покупателей).
- Сумма колонки «Итого» по 77 рублёвым заказам: **694 211 ₽** — ровно столько же даёт прямой
  запрос-агрегат к базе (694 211). По 11 долларовым: **7 264,11 $** против 7 264,11 в базе.
- «Оплачено»: 282 912 ₽ и 111,46 $ — в базе столько же.
- В каждой из 88 строк «Итого» = «Сумма товаров» + «Доставка» − «Скидка»; расхождений — 0.
- Единиц товара в `orders.csv` — 174, в базе — 174.
- Пустых телефонов в файле — 39, в базе — 39; пустых адресов — 6 и 6 (то есть пустоту не подменили нулём).

Три заказа сверены с базой поле за полем (дата, валюта, итого, оплачено, число единиц товара, число строк
позиций), расхождений нет:

| Заказ | Итого | Единиц товара | Строк позиций | Статус в базе |
|---|---|---|---|---|
| № 1 | 4 000 $ | 4 | 1 | pending |
| № 69 | 1 259 ₽ | 1 | 1 | pending |
| № 117 | 11 160 ₽ | 5 | 4 | pending |

## Что стоит знать о данных

Пустая ячейка означает, что значения в базе нет. Пустоту не заменяли нулём или прочерком — «нет данных» и
«ноль» это разные вещи.

- **Телефон не указан в 39 заказах из 88** и у 29 покупателей из 46 — поле не было обязательным.
- **Способ доставки пуст в 33 заказах из 88**: доставка в них не оформлялась через магазин. Стоимость
  доставки в этих заказах — настоящий ноль: итог заказа в базе равен сумме товаров (проверено по всем 33).
- **Имя и адрес отсутствуют в 6 заказах из 88** — в них не заполнен адрес доставки. В `customers.csv`
  без имени 25 карточек из 46, без адреса — 28.
- **Заказ № 19 не содержит ни одной позиции**, его итог равен нулю, и оформлен он на тестовый ящик
  `selfheal-…@chrxn.store` — это служебная запись, помеченная в колонке «Служебная запись».
- **26 покупателей из 46 не сделали ни одного заказа** — регистрации без покупки.
- **Скидок в архиве нет**: ни к одному заказу и ни к одной позиции скидка не применена — проверено по полю
  итогов и по таблице скидочных корректировок (в ней 0 строк), поэтому колонка «Скидка» везде 0.
  Налоговых строк в заказах тоже нет.
- **Отгрузка зафиксирована только у одного заказа** (№ 9, отправлен 2026-07-01). У остальных 87 записи об
  отгрузке в базе нет — статус «не отгружен» означает именно отсутствие записи, а не то, что товар не уехал:
  отправки могли не отмечаться в магазине.
- **Две валюты**: 77 заказов в рублях и 11 в долларах. Суммы по валютам считаются отдельно и в один столбец
  не складываются.
- **Нумерация заказов с пропусками**: номера идут от 1 до 117, а заказов 88 — 29 номеров в базе отсутствуют
  (незавершённые оформления, которые до заказа не дошли).
- **Платежи**: 34 платежа прошли через Робокассу (69 690 ₽, все captured), остальные 26 — через служебный
  провайдер магазина (`system_default`), то есть отмечены вручную, а не получены через платёжный шлюз.
- Статусы оплаты и отгрузки в Medusa не хранятся готовым полем, а выводятся из сумм платежей и отметок об
  отправке; в этом архиве они посчитаны по тем же правилам и переведены на русский.

## Персональные данные

В файлах есть имена, телефоны, адреса и почтовые адреса покупателей. Это персональные данные: архив не
выкладывается в открытый доступ, не публикуется и не заливается в новый магазин; он передаётся владелице
магазина как её собственная выгрузка. CSV-файлы намеренно исключены из git (`.gitignore` рядом).
