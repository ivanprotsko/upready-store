## 1. Выводы для Ивана

1. **`agy -p` умеет всё, что нам нужно для класса «тесты и моки»**: читает файлы, пишет файлы,
   выполняет shell, ищет по коду, ходит в интернет — все пять проверены не по словам модели, а по
   диску и по эталону. Инструментов у агента **57** (полный список выдаёт событие `init` в
   `--output-format stream-json`), включая целый браузер и подагентов.
2. **Главная опасность: `agy` пишет НЕ ТУДА, куда его запустили.** В 2 случаях из 5 задач на запись
   файл ушёл мимо рабочей папки: один раз — в **живой чекаут движка дня**
   (`handoff/day-2026-09-16-oksana-store/ui/lib-extra.test.mjs`, туда же `mkdir -p` и `node --test`),
   другой раз — в `~/.gemini/antigravity-cli/scratch/`. В обоих случаях ответ модели был
   «готово, другие файлы не изменялись» — то есть отчёт агента о месте записи **не является
   свидетельством**. Файл из живого дерева я убрал (копия в raw). Для раннера это значит: только
   одноразовая копия-песочница, приёмка по `diff` копии, и явный запрет абсолютных путей в промпте
   (с этим запретом третий пилот отработал верно).
3. **Пилот «напиши тесты и добейся зелени» проходит с первого раза.** Gemini 3.1 Pro (High) — 21 тест
   за 140,5 с, Gemini 3.8 Flash (High) — 26 тестов за 86,2 с; итоговые строки `node --test ui/` в
   копиях — `# pass 41 / # fail 0` и `# pass 46 / # fail 0` (вместе с прежними 20 своими).
   Ноль итераций исправления, ноль правок чужих файлов.
4. **Тесты не тавтология — проверено мутацией.** Я сломал `renderTemplate` в копии: в наборе Pro
   итоговая строка стала `# pass 19 / # fail 2`, в наборе Flash — `# pass 21 / # fail 5`. Оба набора
   ловят поломку; Flash покрыл функцию плотнее.
5. **Мок внешнего вызова тоже получается.** На задачу «проверить `prView` без реального `gh`» Flash
   (High) сам выбрал `mock.method` на `child_process.execFileSync` через `createRequire` — рабочий
   способ для ESM-модуля, который импортирует CJS, — и проверил не только результат, но и аргументы,
   переданные `gh`. Итоговая строка `# pass 2 / # fail 0`, 102,1 с.
6. **Цена одного пилота — примерно 2 % пятичасовой квоты Gemini.** Весь прогон (39 вызовов, три
   пилота) съел 12 п.п. пятичасового пула (99 % → 87 %) и 3 п.п. недельного (99 % → 96 %). То есть в
   одно пятичасовое окно влезает порядка 50 таких прогонов тестов.
7. **Структурированный вывод работает по-настоящему**: `--json-schema` возвращает отдельное поле
   `structured_output` с уже провалидированным объектом. Для движка это готовый способ получать от
   раннера машинный ответ, а не разбирать текст.
8. **Продолжение сессии работает в обе стороны**: `-c` и `--conversation <id>` помнят предыдущий ход,
   `num_turns` растёт по диалогу. Плюс `--input-format stream-json` позволяет провести несколько
   ходов одной сессии через stdin — форма сообщения в документации не описана, я нашёл её в строках
   самого бинаря: `{"event":"user","message":{"role":"user","content":"…"}}`.
9. **Все 6 проверенных моделей ответили верно** на одинаковый контрольный промпт (арифметика, правка
   JS, факт с источником) — включая `gpt-oss-120b-medium`, который прошлый раз отвечал 503. Разница
   не в правильности, а в цене и скорости: Flash (Low) — 1,7 с и 0 токенов размышления, Pro (High) —
   10,6 с и 570.
10. **Как выглядит отказ по исчерпанию квоты — по-прежнему не замерено.** В логах `agy` за всё время
    ни одного 429 и ни одного `RESOURCE_EXHAUSTED` (найденные «429» оказались миллисекундами старта
    сервера). Провоцировать исчерпание я не стал по условию задачи.

### 2.4 Форматы вывода и структурированный ответ

| Формат | Что печатает | Сырой файл |
|---|---|---|
| `--output-format text` (по умолчанию) | голый текст ответа | `30-format-text.txt` |
| `--output-format json` | одна JSON-строка: `conversation_id`, `status`, `response`, `duration_seconds`, `num_turns`, `usage{input,output,thinking,cache_read,total}` | любой `10-model-*.txt` |
| `--output-format stream-json` | NDJSON, поле `event`: **`init`** (conversation_id, model, cwd, **список 57 инструментов**, `permission_mode`), **`step_update`** (по шагу: `step_index`, `state`, `step_type` = `user_input`/`agent_response`, `text_delta`), **`result`** (то же, что даёт `json`) | `31-format-stream-json.txt` |
| `--json-schema <файл\|строка>` | к JSON-результату добавляются **`structured_output`** (провалидированный объект) и `json_schema`. Важно: в текстовом `response` модель дописывает служебные ключи (`toolAction`, `toolSummary`) — читать надо `structured_output`, не `response` | `32-format-json-schema.txt`, схема `schema-city.json` |
| `--input-format stream-json` | несколько ходов **одной** сессии через stdin, по одному `result` на ход. Требует `--output-format stream-json` и **`-p=''`** (голый `-p` съедает следующий флаг как промпт — CLI честно об этом сообщает) | `110-input-stream.ndjson`, `111-input-stream-out.txt` |

Форма входного сообщения в документации не описана; найдена в строках бинаря
(`stream input "user" message is missing the "message" field`):

```
{"event":"user","message":{"role":"user","content":"Запомни число 4242. Ответь: ок."}}
{"event":"user","message":{"role":"user","content":"Какое число я просил запомнить? Только число."}}
```

Замер: два `result`, один и тот же `conversation_id`, `num_turns` 1 → 2, второй ответ — `4242`.
То есть контекст между строками stdin сохраняется.

### 2.5 Продолжение сессии

| `-c -p "Какое кодовое слово?"` | 2 | **`ВОЛЬФРАМ-77`** | `41-session-continue.txt` |

вести с раннером многоходовой диалог (раунд правок после приёмки) без пересылки контекста.

### 3.5 Инцидент: запись мимо рабочей папки

Пилот на Pro (High) заявил «создал файл `ui/lib-extra.test.mjs`, TESTS 41/41». Файла в его рабочей
копии не было. По стенограмме самого `agy`
(`65-pilot-pro-transcript.jsonl`, шаги 18–26) он:

1. прочитал `lib.mjs` по абсолютному пути **живого** движка;
2. выполнил там `mkdir -p …/ui`;
3. записал туда `lib-extra.test.mjs`;
4. там же выполнил `node --test` — и прогон был зелёным, потому что в живом `ui/` лежат те же тесты.

Ни одного упоминания пути его собственной рабочей папки в стенограмме нет. Копия файла сохранена
(`62-pilot-pro-lib-extra.test.mjs`), из живого дерева файл удалён, `git status` по `ui/` чист.

Второй случай того же класса — проба `--mode accept-edits`: «создай в этой папке `mode-probe2.txt`»
→ файл лёг в `~/.gemini/antigravity-cli/scratch/mode-probe2.txt`.

Счёт по всем задачам на запись этого прогона: **3 из 5 — в рабочую папку, 2 из 5 — мимо**.
Третий пилот (мок), где в промпте стояло «пиши только относительно текущей рабочей папки, абсолютные
пути вне неё не использовать», записал верно.

## 4. Квота: журнал и цена

## 5. Рекомендация для поля `runner: "agy"` движка

**Модель: `gemini-3.8-flash-high`.** По замерам она и быстрее Pro (86,2 с против 140,5 с на одной
задаче), и написала более плотные тесты (26 против 21, мутацию ловит пятью падениями против двух), и
именно она записала файлы туда, куда её запустили, во всех своих прогонах. Pro (High) в единственном
успешном прогоне ушёл писать в чужое дерево.

**Командная строка:**

```
agy -p "<промпт>" --dangerously-skip-permissions \
    --output-format json --print-timeout <N>m --model gemini-3.8-flash-high
```

**Что обязательно добавить в преамбулу промпта раннера** (обе строки проверены живьём):

```
Работай сам: не создавай подагентов и фоновых задач, не используй define_subagent/invoke_subagent/schedule.
Все команды запускай синхронно и дожидайся вывода.
Пиши файлы ТОЛЬКО относительно текущей рабочей папки; абсолютные пути вне неё не использовать.
```

Первая строка снимает зависание на `waiting for background task(s)` (одна попытка из двух умерла
именно так). Вторая — единственное, что отличало прогон, записавший верно, от прогона, записавшего
в живой чекаут.

**Ограничения, которые движок должен соблюдать:**

1. **`--effort` не передавать** вместе с `gemini-*-{high,low,medium}`: rc=1, `invalid model selection`.
   Усилие уже в id модели (замер `130-effort.txt`).
2. **`--print-timeout` ставить всегда** — по умолчанию 5 минут, длинная задача обрывается молча.
3. **Рабочая папка — одноразовая копия**, и приёмка результата — `diff` копии против эталона
   плюс проверка, что живое дерево не изменилось. Отчёт агента о том, куда он записал, доверия не
   заслуживает (2 случая из 5).
4. **Машинный ответ брать через `--json-schema` → `structured_output`**, а не разбором текста:
   в `response` модель дописывает служебные ключи.
5. **Раунд правок — через `--conversation <id>`**, а не новым вызовом: контекст сохраняется,
   `num_turns` растёт.
6. **Порог квоты**: один прогон тестов — 2 п.п. пятичасового пула Gemini. Текущий `quotaMinPct` = 10 %
   оставляет запас примерно на пять прогонов; при пакете тяжёлых задач порог разумно поднять до 15 %.
7. Тяжёлые пакеты ставить **сразу после границы пятичасового окна** (границы пула Gemini в WITA:
   03:34, 08:34, 13:34, 18:34, 23:34).

## 6. Не замерено / открытые вопросы

- **Как выглядит отказ по исчерпанию квоты.** В логах `agy` (126 файлов) ни одного HTTP 429 и ни
  одного `RESOURCE_EXHAUSTED` (`120-quota-log-grep.txt`, `122-429-context.txt`: два совпадения «429»
  оказались миллисекундами старта сервера). В бинаре есть строки TUI `Quota available` /
  `Quota exhausted` и код `RESOURCE_EXHAUSTED` — то есть форма отказа существует, но её текст в
  print-режиме не наблюдался. Провоцировать исчерпание было запрещено условием задачи.
- **Порядок команд на странице справочника.** Модель назвала три команды алфавитом; страница
  рисуется JS, и по сырому HTML порядок проверить нельзя. Сам факт похода на страницу подтверждён.
- **Почему Pro ушёл писать в чужое дерево.** Стенограмма фиксирует, ЧТО он это сделал, но не
  показывает, откуда взялся абсолютный путь. Два кандидата — большой `cache_read_tokens` (271 898,
  то есть переиспользованный контекст прошлых разговоров) и то, что документы копии сами повсюду
  называют абсолютный путь оригинала. Различить можно чистым прогоном на копии без документов.
- **`--project` / `--new-project`** не проверялись (проверен только `--add-dir`).
- **`claude-opus-4-6-thinking`, модели 3.7/3.6-flash, medium-варианты** — не гонялись, чтобы не жечь
  квоту: контрольный промпт прошли 6 моделей из 14.
- **Мультиагентность `/boost` и подагенты** в print-режиме не раскрываются: `/boost` печатает
  «Executing Solo Routine», а единственная попытка агента уйти в фоновую задачу кончилась зависанием.
  Как это работает в TUI — не замерено.
- **`--sandbox`**: сеть из него доступна; что именно он ограничивает («terminal restrictions») —
  не замерено.
