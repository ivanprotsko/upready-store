# Пачка: панель — экраны, которых нет, и один адрес по http

Четыре дырки экранов владелицы. API под тремя из них уже готово — не хватает ровно экрана.
Источники (прочитай целиком):
- `logs/accept-t11-seo-redirects-2.findings.md`, раздел «Перенос, а не недоделка»;
- `artifacts/accept-t11-seo-redirects-3/REPORT.md`, «Нитки», пункты 1 и 4;
- `artifacts/q03-gap-recheck/gap-recheck.md`, раздел «7. Мелочи…» (страница `qa-test-q02`) и раздел
  «Осталось критичного», пункт 2 (Result URL по `http://`).

## Что замерено

1. Маршруты `/tenants/redirects*` живые, **экрана в панели нет** — таблица редиректов остаётся API-only.
2. Маршрут `/tenants/seo-verification` живой, **поля в панели нет** — владелице некуда вставить код
   подтверждения Яндекс/Google.
3. На живом магазине осталась страница `qa-test-q02` от приёмки: **панель не умеет удалять страницы**.
4. Экран «Приём оплат» выдаёт владелице **Result URL по `http://`** — Robokassa такой адрес не примет
   (замер q03; боевые креды при этом от Оксаны, это отдельная строка в `needs-ivan.md`, но адрес чиним мы).
5. Ни у `/tenants/redirects*`, ни у `/tenants/seo-verification` **нет seam-спека**, хотя он есть у всех
   соседних ресурсов тенанта (`tenants-pages.spec.ts`, `tenants-domains.spec.ts`).

## Что сделать

Экраны в стиле соседних экранов панели (канон `~/upready/packages/geist-kit/AGENTS.md`, правило 27; смотри,
как сделаны «Страницы» и «Домены»): список, создание, правка, удаление; человеческие подписи, без сырых ключей
(правило класса из f12). Удаление страницы — с подтверждением. Result URL строится по схеме внешнего адреса
магазина, а не хардкодом. Seam-спеки на оба ресурса — в том же PR.

## Критерий готовности

Стенд с клоном базы магазина Оксаны, прогон **кликами** (Playwright, системный Chrome — как в приёмке t15):
- завела правило редиректа → старый адрес витрины отдал 301 на новый; изменила цель → 301 поехал на новую;
  удалила → адрес снова 404. Скриншот экрана 1280×900;
- вставила код верификации → `curl -s <главная магазина> | grep <код>` находит его в `<head>`. Скриншот;
- удалила страницу из панели → `/ru/pages/<ключ>` отдаёт 404. Скриншот. **Отдельным шагом** снеси
  `qa-test-q02` на ЖИВОМ магазине и покажи 404 (это единственное касание живого — запись через панель, не в БД);
- экран «Приём оплат» показывает Result URL, начинающийся с `https://`. Скриншот.
Seam-спеки зелёные, строка `ℹ fail` всего файла приложена. Отчёт `artifacts/docs/b10-panel-gaps/report.md`.
Один PR на всю пачку.
