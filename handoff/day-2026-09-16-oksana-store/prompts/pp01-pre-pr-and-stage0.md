# pre-pr скрипт и машинный этап 0 приёмки (pp01)

Задача {{TASK_ID}} — заказ Ивана 2026-09-18 05:36 WITA, п. 2 («если это может улучшить нашу работу, то запускай в работу») и п. 1.1 от 04:53 (каскад приёмки, этап 0 машинный). Факт, ради которого задача: за день 22 из 34 отклонённых раундов приёмки были «процессными» (ветка отстала от dev, конфликт HANDOFF.json, PR CONFLICTING, незакоммиченные файлы), хотя инструкция в `{{MISSION_DIR}}/prompts/_worker-preamble.md` (строки про merge origin/{{BASE}} и лечение CONFLICTING) стояла у каждого воркера. Инструкция агенту не равна гейту — нужен детерминированный скрипт.

## Что сделать (ветка {{BRANCH}} от {{BASE}}, PR на {{BASE}})
1. `{{MISSION_DIR}}/pre-pr.sh` — bash, запускается воркером из его worktree ПЕРЕД `gh pr create` и после каждого push. Шаги, каждый печатает строку `PRE-PR <шаг>: ok|fail <детали>`:
   - `git fetch origin {{BASE}}`; если ветка позади (`git rev-list --count HEAD..origin/{{BASE}}` > 0) — `git merge --no-edit origin/{{BASE}}`;
   - при конфликте: если конфликтует ТОЛЬКО `HANDOFF.json` — взять версию базы (`git checkout origin/{{BASE}} -- HANDOFF.json`, add, commit с префиксом `IVAN_OK=1` и литеральным pathspec); любой другой конфликтующий файл — прервать merge (`git merge --abort`), напечатать список файлов, rc=2;
   - незакоммиченные изменения в отслеживаемых файлах — rc=4 со списком (воркер должен сам решить, что коммитить);
   - `git push -u origin HEAD`; затем проверка `git rev-list --count HEAD..origin/{{BASE}}` = 0;
   - если PR уже есть: `gh pr view --json mergeable,mergeStateStatus` с ожиданием до 60 с (6 × 10 с) пока `mergeable` = UNKNOWN; CONFLICTING → rc=3;
   - финальная строка `PRE-PR: OK` или `PRE-PR: FAIL <код> <причина>`. Все внешние вызовы — с явными таймаутами; никакого интерактива.
2. `{{MISSION_DIR}}/accept-stage0.sh <task-id> <pr-number> <out-dir>` — машинный этап 0 приёмки, идёт ДО модели-приёмщика. Проверки, каждая — запись в `<out-dir>/stage0.json` (`{check, status: pass|fail|skip, details, files[]}`) и строка в `<out-dir>/stage0.md`:
   - PR: `mergeable` ≠ CONFLICTING, ветка не позади базы;
   - diff PR не трогает `HANDOFF.json`, `state.json`, `tasks.json` движка (если трогает — fail с файлами);
   - сканер секретов по diff (добавленные строки): ключи вида `AQ.`, `sk-`, `ghp_`, `AKIA`, `-----BEGIN`, `password=`/`token=` с непустым значением, `YANDEX_ID_PASSWORD`/`*_SECRET=` со значением; исключения — имена переменных без значений и `.env.example`;
   - детектор выключенных тестов в diff: `.skip(`, `.only(`, `xit(`, `xdescribe(`, `test.todo(`, `it.skip`, правки `testPathIgnorePatterns`/`exclude` в конфигах тестов — fail, если нет строки-обоснования в теле PR;
   - lint/tsc/tests затронутых пакетов monorepo (по `AGENTS.md` репозитория — используй те команды, что там названы; фильтр по пакетам из diff; общий таймаут 15 мин; при отсутствии тестов в пакете — skip с пометкой);
   - итог: `STAGE0: PASS|FAIL <список проваленных проверок>`, rc=1 при любом fail.

Правки промптов: в `prompts/_worker-preamble.md` заменить текстовую инструкцию о merge/CONFLICTING на приказ запускать `{{MISSION_DIR}}/pre-pr.sh` перед `gh pr create` и после каждого push, и не создавать PR при `PRE-PR: FAIL`; в `prompts/_acceptor.md` — первым действием запускать `accept-stage0.sh {{TASK_ID}} <PR> <папка артефактов раунда>` и при `STAGE0: FAIL` выносить вердикт отклонения с находками из stage0.md, не тратя раунд модели на чтение кода.

Тесты: `{{MISSION_DIR}}/ui/pre-pr.test.mjs` и `ui/stage0.test.mjs` на `node:test` с временными git-репозиториями (bare origin + два клона) и шимом `gh` в PATH (скрипт, печатающий заданный JSON): сценарии pre-pr — ветка в актуальном состоянии; отстала и сливается чисто; конфликт только HANDOFF.json (лечится, коммит есть); конфликт в чужом файле (rc=2, список); незакоммиченные правки (rc=4); PR CONFLICTING (rc=3). ## Правила
- Ничего не менять в dispatcher.mjs / lib.mjs / state.json / tasks.json движка — они принадлежат штабу; своё — только новые скрипты, тесты и два промпта.
- Скрипты не должны требовать интерактива и не должны ходить на живой хост; `gh` только к PR текущего репозитория.
- Коммиты только с `IVAN_OK=1`, литеральные pathspec; сам pre-pr.sh прогони на своей же ветке перед созданием PR (это и есть приёмка п. 1).

Приёмка: {{ACCEPTANCE}}. Последняя строка — `RESULT: OK <URL PR>` или `RESULT: FAIL <причина>`.
