## Build
1. Backend. `PUT /tenants/wb/key` `{ api_key }` and `DELETE /tenants/wb/key`; `PUT /tenants/ozon/key` `{ client_id, api_key }` and `DELETE /tenants/ozon/key`. Validate non-empty (zod, like payment-settings validators). Write the encrypted payload into the READ slot with the same helper family the payment-settings route uses — if there is no shared `writeTenantSecretSlot`, extract one into `tenant-secrets/slot.ts` and make payment-settings use it too (one writer, rule 20). Response = masked settings (`set`, `last4`) + for WB the `inspectToken` summary (readOnly / bits / expiry) — never the key itself. The key never appears in logs, audit tables (`wb_api_call`, `marketplace_write_audit`) or error messages — add a test that greps the captured log and response bodies for the literal.
   Invariant (Ivan 2026-09-16 02:46 WITA): the product only READS marketplaces. A key carrying write bits is accepted and stored, the UI shows «ключ с правами записи: магазин их не использует»; the WRITE slot (`wildberries_write`) is NEVER populated from this form — it stays the domain of w20 (wb_write_enabled, consent, WB_WRITE_LIVE). Test it: after PUT the write slot row is absent/unchanged.
2. Panel. On `/settings/wildberries` a card «Ключ API»: state line (`не сохранён` / `сохранён ••••last4`), a password-type input + «Сохранить», «Удалить» with a confirm dialog; after save the status block re-fetches (rights, expiry, tables — no reload). New page `/settings/ozon` (Client-Id + API key, status via `/tenants/ozon/status`), reachable from the hub and the «Маркетплейсы» sidebar section. The hub `/settings/marketplaces` lists every integration with its state and link: Wildberries, Ozon, Robokassa → `/settings/payments`, Доставка (ApiShip/CDEK) → the route i02 ships (if i02 is not merged when you finish, link to `/settings/delivery` and label it «скоро»). Remove all CLI hints from owner-facing strings (ru.json, en.json, adapter hints). Geist canon: read `~/upready/packages/geist-kit/AGENTS.md` first; reuse the payments form components.
3. Tests. Backend unit/HTTP spec for PUT/DELETE (encrypted at rest — the raw table row does not contain the literal; masked response; write slot untouched; 401 without owner auth; tenant isolation — tenant A cannot read/replace tenant B's key). Panel e2e (Playwright, the way the repo already does it): owner enters a key on a stand → the page shows rights within 10 s; delete → «не сохранён».
4. Docs: a short owner-facing section «Как подключить интеграции» (ru) in the panel help or `docs/` — steps in the panel, no CLI.
