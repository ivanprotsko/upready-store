Reading of the order (staff): point 2.1 refines 1.1.1. The section «Подключение» IS `/settings/integrations` — a hub that holds ONLY credential forms, one sub-page per service: `/settings/integrations/wildberries`, `/settings/integrations/ozon`, `/settings/integrations/robokassa`, `/settings/integrations/apiship`, `/settings/integrations/cdek`. The marketplace SCREENS (what the owner sees about a marketplace: connection state, rights, expiry, loaded tables, categories, sync state) live at `/settings/marketplaces/wildberries` and `/settings/marketplaces/ozon` and carry NO key fields — they link to the integration page. Payment and delivery BEHAVIOUR settings (test mode toggle, markup, free-shipping threshold, zones, tariff mode) stay where they are (`/settings/payments`, `/settings/delivery`) and link to the integration page for credentials. If the code proves one of these placements impossible, write why in decision.md and pick the closest reading — never ask.
