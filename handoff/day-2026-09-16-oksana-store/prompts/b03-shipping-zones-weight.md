# Пачка: настоящая доставка — региональные зоны РФ и правило «цена за кг по зонам»

Источник: `artifacts/q03-gap-recheck/gap-recheck.md`, «Осталось критичного», пункт 4. Сейчас живьём два способа доставки с фиксированной ценой, заготовка тарифа по весу и одна зона «Все страны магазина». Оксана просила расчёт «цена за кг по зонам» (её обращение #463839 в переписке; текст просьбы — в `research/` и `artifacts/q02-qa-owner/`, если нужен контекст).

## Что сделать
1. Зоны доставки внутри РФ в панели: владелица создаёт зоны из регионов/городов (заготовь набор по умолчанию: Москва и МО, Санкт-Петербург и ЛО, Центр, Северо-Запад, Юг, Поволжье, Урал, Сибирь, Дальний Восток) — с редактированием.
2. Правило стоимости «базовая цена + цена за кг сверх N кг» по зоне; вес берётся из карточек товаров (проверь, что у товаров Оксаны вес задан или дай импорт из `metadata`).
3. Витрина: на оформлении заказа стоимость доставки считается по адресу (регион) и весу корзины; покупатель видит зону и цену до оплаты.
4. Хотя бы одна реальная служба как способ: «СДЭК (расчёт по тарифу магазина)» с полем трек-номера — без API-интеграции, но с честным названием и инструкцией владелице.

## Критерий готовности
Стенд с клоном базы Оксаны: создана зона, правило, оформлен заказ в два разных региона с разной ценой доставки (скриншоты + JSON заказа), юнит-тесты расчёта, отчёт `artifacts/docs/b03-shipping-zones-weight/report.md`. Один PR.
