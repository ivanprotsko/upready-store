## Зонтик: ISO/IEC 25010:2023 — модель качества продукта

Восемь характеристик, по которым выставляется итоговая оценка A–E: функциональная пригодность, производительность, совместимость,
удобство использования (включая доступность), надёжность, безопасность, сопровождаемость, переносимость. Каждая находка отнесена
к одной из них.

## Безопасность

- **OWASP ASVS 4.0.3, уровень L2** — норма для приложения с персональными данными и платежами: V2 аутентификация, V3 сессии,
  V4 контроль доступа (в т. ч. §4.1.3 «принцип наименьших привилегий», §4.2.1 IDOR), V5 валидация и кодирование, V6 криптография,
  V7 логирование и ошибки, V8 защита данных, V9 транспорт, V12 файлы, V13 API, V14 конфигурация.
- **OWASP Top 10:2021** — A01 Broken Access Control, A02 Cryptographic Failures, A03 Injection, A04 Insecure Design,
  A05 Security Misconfiguration, A06 Vulnerable Components, A07 Identification & Authentication Failures, A08 Software & Data
  Integrity, A09 Logging & Monitoring Failures, A10 SSRF.
- **OWASP API Security Top 10:2023** — API1 BOLA (объектный доступ), API2 аутентификация, API3 избыточные свойства объектов,
  API4 отсутствие лимитов, API5 функциональный доступ, API6 бизнес-потоки, API7 SSRF, API8 misconfiguration, API9 инвентарь,
  API10 небезопасное потребление внешних API.
- **CWE** для точной классификации (CWE-79 XSS, CWE-89 SQLi, CWE-284 access control, CWE-352 CSRF, CWE-798 hardcoded creds,
  CWE-918 SSRF).
- **PCI DSS 4.0** — только вопрос области: карточные данные не должны касаться наших серверов (делегирование PSP, SAQ A).
- **Персональные данные** — 152-ФЗ (локализация, согласие, минимизация, политика на сайте) и GDPR как ориентир по минимизации и срокам
  хранения.
- **Мультитенантность** — каждая выборка данных фильтруется по тенанту на сервере; идентификатор тенанта выводится из запроса
  (хост, ключ, JWT), никогда не берётся из тела запроса клиента.

## Веб-качество витрины

- **Core Web Vitals** (Google, пороги «хорошо»): LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1; TTFB ≤ 0,8 с как вспомогательная.
- **Next.js 15 App Router** — границы server/client компонентов, кэширование `fetch`/`revalidate`/теги, `next/image` с `sizes` и
  `priority` для LCP, `next/font`, стриминг и `loading.tsx`, `generateMetadata`, конфигурация сегментов маршрутов.
- **WCAG 2.2 уровень AA** — POUR; ключевые критерии: 1.1.1 альтернативный текст, 1.3.1 структура, 1.4.3 контраст 4.5:1,
  1.4.11 контраст нетекстовых элементов 3:1, 2.1.1 клавиатура, 2.4.4 назначение ссылок, 2.4.7 видимый фокус, 2.5.8 размер цели
  24×24 px, 3.1.1/3.1.2 язык страницы и частей, 4.1.2 имя/роль/значение.
- **Google Search Essentials** — canonical, hreflang на все 36 локалей плюс x-default, sitemap и robots, структурированные данные
  schema.org Product/Offer/BreadcrumbList, `noindex` на корзине/оформлении/кабинете.
- **i18n** — ICU MessageFormat, формы множественного числа для ru (one/few/many), форматирование дат/чисел/валют через `Intl`
  с локалью, полнота 36 каталогов (парити).

## Бэкенд и данные

- **Архитектурные соглашения Medusa 2** — модули со своими моделями и сервисами, workflows с компенсацией, links вместо
  межмодульных FK, тонкие маршруты API, валидаторы zod, чтение через `query.graph` с явными полями.
- **Дизайн REST API** — коды состояния, пагинация с максимальным размером страницы, идемпотентность мутаций, единая форма ошибки,
  версионирование, инвентарь маршрутов.
- **База данных** — индексы на FK/тенант/поисковых колонках, уникальные ограничения (например, handle в пределах тенанта),
  миграции в git, обратимые, схема отдельно от данных, безопасные значения по умолчанию.
- **Фоновая работа** — идемпотентность, повторы с экспоненциальной задержкой, размыкатель на внешние API, блокировки от параллельных
  запусков.

## Инженерные практики и эксплуатация

- **12-factor app** — I кодовая база, III конфигурация в окружении, IV backing services, V сборка/релиз/запуск, VI процессы без
  состояния, IX disposability, X паритет dev/prod, XI логи как поток.
- **DORA** — частота деплоев, время до продакшена, MTTR, доля неудачных изменений (по устройству пайплайна, не измерением).
- **Google SRE** — health checks, откат, SLO и алерты, runbook, бэкапы с проверкой восстановления.
- **Пирамида тестов** — много быстрых unit, меньше интеграционных, немного e2e; тесты в CI как обязательные проверки.
- **OpenSSF Scorecard (выборочно)** — защита ветки, закреплённые версии actions, автообновление зависимостей, SAST, подписанные релизы.
- **TypeScript** — `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`; ESLint `react-hooks`, `jsx-a11y`,
  `@typescript-eslint` recommended-type-checked; единый Prettier.
- **Conventional Commits** и семантическое версионирование; лицензионная чистота зависимостей.
- **Сопровождаемость (ISO 25010)** — модульность, переиспользование, анализируемость (размер файлов/функций, `any`, `ts-ignore`),
  изменяемость, тестируемость; актуальность документации (`AGENTS.md`, `README.md`, спецификации).

## Шкала серьёзности

- **Critical** — эксплуатируемая утечка данных между магазинами или покупателями, обход аутентификации, потеря денег/заказов, падение
  системы для всех тенантов.
- **High** — уязвимость с реальным путём эксплуатации при дополнительных условиях; нарушение закона (152-ФЗ, оферта); нет отката/бэкапа.
- **Medium** — ухудшение качества с измеримым эффектом (CWV, WCAG AA, N+1, отсутствие тестов критичного пути).
- **Low** — гигиена, консистентность, документация.
- **Info** — наблюдение без действия.

## Шкала итоговой оценки

A — соответствует стандартам, только Low/Info; B — есть Medium, нет High; C — есть High, есть план; D — есть Critical или несколько
High без плана; E — систематические нарушения.
