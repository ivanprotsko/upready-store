# Абстрактный набор данных: один стартовый каталог под любую тему

**Статус:** спека трека «абстрактные наборы данных», задача `t-2026-09-12-catalog-taxonomy`,
2026-09-12. Решение Ивана (второе за день, `GLOSSARY.md` §2): **ОДИН набор, подходящий под
любую тему**; наборы под конкретную тему — бэклог `t-2026-09-12-abstract-sets-per-theme`.
Пары картинок «светлый/тёмный режим» — другая задача `t-2026-09-12-mode-image-pairs`
(`GLOSSARY.md` §3); здесь рендерится светлая версия и держится промпт под близнеца.

## 1. Что это и где лежит

Набор = предзаполнение магазина, у которого сфера торговли не указана. Формат — существующий
профиль магазина, без второго формата:

```
apps/backend/src/migration-scripts/data/profiles/abstract/
  profile.json            upready.store-profile/v0, блок dataset.kind = "abstract", themes = "any"
  catalog/{categories,product-options,products,collections}.json
  i18n/{en,ru}.json       названия и описания на двух языках
  design/style-board.md   серия, промпт, гейт — сгенерирован
  theme.json              копия пресета geist (схема требует пресет; тема тенанта живёт в его документе)
  media/manifest.json     upready.store-media-manifest/v0 — из реальных рендеров
  media/*.webp            gitignored, как у всех профилей; байты — в /static/store-profiles/abstract/
```

Всё, кроме `media/`, **генерируется** из одного источника —
`apps/backend/scripts/abstract-datasets/definitions.mjs` (`build.mjs` пишет, `--check` ловит дрейф).
Валидатор профилей проходит: `node scripts/validate-store-profile.mjs abstract`.

## 2. Содержимое

| Что | Сколько | Имена |
|---|---|---|
| Корневые категории | 2 | Forms / Формы, Sets / Наборы |
| Категории-листья | 5 | Spheres, Cubes, Cylinders; Pairs, Stacks |
| Товары | 10 | `<Form> No. <n> · <finish>`: Sphere No. 1 · Chalk white … Stack No. 2 · Graphite on white |
| Варианты | 22 | опция Size (Small 8 см / Medium 12 см / Large 18 см) у шести товаров, один размер у четырёх |
| Коллекции | 2 | New arrivals (первые номера), Bestsellers (вторые) |
| Изображения | 16 | 10 hero-кадров товаров, 5 плиток категорий, 1 баннер главной |

Предметы — **абстрактные формы**: матовый гипс, меловой белый / средний серый / графит, без
цвета, без маркировок, без узнаваемого товара. Описания честно говорят, что это стартовый
каталог, и заканчиваются приглашением заменить товар своим. Цены — заглушки $24–$154.

**Почему нейтральная серия.** Набор один на семь тем витрины, значит он не подстраивается под
палитру, а обязан не спорить ни с одной: у предметов нет цвета, фон — нейтральный серый.

## 3. Серия и генерация

Одна сетка 4×4 на `fal-ai/nano-banana-pro` 4K ($0.30 по леджеру `wave-registry.mjs`),
шестнадцать ячеек по 1024 px: одна экспозиция, один фон, одна камера — потому кадры и есть одна
серия. Порядок ячеек, промпт и гейт — в `design/style-board.md` набора. Скрипты:

```bash
cd apps/backend
node scripts/abstract-datasets/render.mjs --mode light            # dry run, промпт и ячейки
node scripts/abstract-datasets/render.mjs --mode light --spend    # ОДИН платный запрос, леджер первым
node scripts/abstract-datasets/slice.mjs  --mode light            # границы найдены, webp, гейт, манифест
node scripts/validate-store-profile.mjs abstract                  # схема + sha256 файлов
```

Сырьё — `artifacts/media/abstract/raw/` (PNG сетки, sidecar JSON с промптом по половинам,
замер границ, вырезанные ячейки), не удаляется (42c).

**Промпт разложен на половины** (`definitions.mjs`): `MODES.light` / `MODES.dark` = фон + свет;
`OBJECTS` + `CAMERA` = общее, слово в слово. Тёмный близнец каждого кадра = те же 16 клауз
ячеек + вторая половина, `render.mjs --mode dark` — но заказывает его задача
`t-2026-09-12-mode-image-pairs`, когда приедет формат хранения пары; здесь ось режима в манифест
и схему НЕ добавляется (в `params.mode` записано только «какая половина была послана»).

**Гейт серии** (`slice.mjs`): границы панелей найдены `grid-measure.py`, а не взяты по четвертям;
яркость фона каждой ячейки в пределах ±10 уровней от медианы; передний план ≥ 8 % ячейки; на
срезанных краях нет линии-остатка. Проваленная ячейка идёт в манифест как `flagged` с причиной,
а не прячется. Плюс глаза (18f): контактный лист смотрится, узнаваемый предмет/текст/цвет —
`flagged` с причиной.

## 4. Засев магазина мастера

Магазин, созданный `POST /api/demo/onboarding`, получает ЭТОТ набор при любой выбранной теме:

1. Витрина после создания тенанта и входа владельца вызывает `POST /tenants/seed` с `preset`.
2. Бэкенд выбирает набор: профиль с `dataset.kind = "abstract"`, у которого `themes` содержит
   `preset` (наборов под тему сегодня нет), иначе `themes = "any"` — универсальный.
3. Воркфлоу `seed-tenant-dataset` создаёт копию набора ДЛЯ ЭТОГО тенанта: категории (дерево,
   `metadata.image_url`/`image_alt`, связь tenant↔category), коллекции, товары (варианты, цены во
   всех валютах регионов из таблицы курсов сида, картинки по абсолютному URL, канал продаж
   тенанта, связь tenant↔product). Handle в Medusa уникален глобально, поэтому копия получает
   суффикс handle тенанта: `sphere-1-<tenant>`, `spheres-<tenant>`, `new-arrivals-<tenant>`.
   Опция `Size` — ОБЩАЯ библиотечная строка Medusa (`is_exclusive = false`, title уникален на всю
   базу): шаг `ensure-shared-product-options` находит её или создаёт и добавляет значения набора
   (объединение с тем, что уже есть), а товары ссылаются на неё по id — как засев профилей
   (`lib/products.ts`). Опция, заведённая инлайн при создании товара, эксклюзивна для него, и
   витрина, группируя фильтры по id опции, показывала шесть селектов «Size» вместо одного
   (замер приёмщика 2026-09-12, `t-2026-09-12-seed-option-filter-duplicates`; после починки —
   одна группа на 6 товаров, замер 13:02 WITA на локальном стенде). Повторная проверка задачи
   (2026-09-29, стенд `upready_store_ex_08` восстановлен из `upready_store_live_copy`,
   backend/storefront `:9608`/`:8608`): свежий тенант после `POST /tenants/seed` даёт ровно один
   фильтр на все 6 товаров с вариантами; откат по отдельности каждого из двух фиксов не
   воспроизводит дефект (любой из них в одиночку уже прячет симптом), нужны оба сразу — на
   отдельном тенанте так и было проверено: временно откатив шаг `ensure-shared-product-options`
   ВМЕСТЕ с группировкой по названию в `option-filter-groups.ts`, получили исходные шесть
   селектов «Size». Оба под юнит-тестами:
   `abstract-datasets.unit.spec.ts` (`sharedOptions`) и `option-filter-groups.test.ts`
   (группировка по названию, не по `option.id`); диф на этот повторный замер не открывался.
4. Идемпотентно: у тенанта уже есть товары или категории → ничего не создаётся, ответ говорит
   почему. Ошибка засева не роняет онбординг: магазин создан, причина возвращается на экран.
5. Витрина затем пишет документ главной (`PUT /tenants/home`) с `hero.image_url` баннера набора;
   плитки категорий на главной берутся из СОБСТВЕННЫХ категорий магазина с картинкой.

Адрес медиа: `STORE_PROFILES_MEDIA_BASE_URL` (как у `seed-mt-demo`), иначе родитель
`STORE_MEDIA_BASE_URL`; нет ни того, ни другого — громкая ошибка, а не пустая картинка. На проде
байты набора должны лежать в `/opt/upready-store/media/abstract/` (том `compose.mt.yml`), это
шаг деплоя, не кода.

## 5. Приёмка (живой продукт)

- Магазин, созданный мастером на проде, открывается с категориями, товарами и картинками.
- Абстрактность видна глазами: на картинках нет узнаваемого конкретного товара.
- Набор выживает на любой теме: переключение темы на живом магазине не ломает карточки.
- 67 существующих товаров размечены (`TAXONOMY.md` §4), непокрытых нет, кросс-сферный назван.
