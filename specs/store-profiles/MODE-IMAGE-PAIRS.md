# Парные изображения под режим — конвенция `upready.mode-image-pair/v1`

Канон оси: `specs/catalog-taxonomy/GLOSSARY.md` §3. Дизайн-стадия и замеры:
`artifacts/docs/2026-09-12-mode-image-pairs-mockup.md`. Задача `t-2026-09-12-mode-image-pairs`.

Одна ось данных на три поверхности витрины: герой, категория товаров, товар. Свойство ДАННЫХ, не
темы: пара живёт у изображения, а не у пресета.

## 1. Правило имени

Базовое поле остаётся на месте и значит «показывать в любом режиме». Тёмная версия кладётся рядом,
под именем базового поля плюс метка режима, в том регистре, который принят в этом файле: `_dark` в
рантайм-документах (snake_case), `Dark` в JSON профилей (camelCase). Метка ОДНА, разные регистры —
это одно правило на двух языках записи, а не две конвенции.

Светлой версии отдельного поля НЕТ намеренно: база и есть светлая версия. Второе поле под тот же
кадр было бы вторым способом сказать одно и то же — и первым источником расхождения.

| Поверхность | База | Тёмная версия | Где валидируется |
|---|---|---|---|
| Герой | `content.hero.image_url` | `content.hero.image_url_dark` | `apps/backend/src/api/tenants/home/validators.ts` |
| Категория | `metadata.image_url` | `metadata.image_url_dark` | `product_category.metadata` (jsonb, без схемы) |
| Товар | `thumbnail`, иначе `images[0].url` | `metadata.image_url_dark` | `product.metadata` (jsonb, без схемы) |

Описание изображения (`metadata.image_alt`) — ОДНО на пару: это один предмет при двух освещениях.

## 2. Правило чтения

```
version(mode) = mode === "dark" ? (dark ?? base) : base
```

Пара необязательна на каждой из трёх поверхностей. Отсутствие тёмной версии — нормальное состояние,
не дефект: оба режима показывают базу. Пустого прямоугольника не возникает ни в одном состоянии; если
нет и базы, поверхность ведёт себя точно как до этой конвенции (герой не рендерится, плитка
показывает нейтральную рамку, карточка — плейсхолдер Medusa).

Документ тенанта остаётся `upready.tenant-home/v1`. Добавлено НЕОБЯЗАТЕЛЬНОЕ поле: документ без него
читается, валидируется и сохраняется как раньше. Миграции нет.

## 3. Правило отрисовки

Выбор версии обязан пережить клик по переключателю режима: `nav-mode-toggle` и
`bottom-nav-mode-toggle` меняют `data-mode` на `<html>` в браузере, без перезагрузки
(`apps/storefront/src/lib/theme/apply.ts`). Поэтому:

1. **Обе версии рендерятся в HTML, выбирает CSS по `[data-mode]`.** В этом репозитории готово:
   `apps/storefront/tailwind.config.js` — `darkMode: ["selector", '[data-mode="dark"]']`.
2. **Неактивный слой — `loading="lazy"` и никогда `priority`.** Замерено на Chromium, WebKit и
   Firefox: скрытое `display:none` изображение с `lazy` не запрашивается до того, как переключение
   его покажет; без `lazy` запрашивается сразу. Это то, что делает конвенцию бесплатной на первой
   отрисовке.
3. **Рамка держит размер.** Обе версии в одном контейнере с фиксированным соотношением сторон —
   переключение не двигает вёрстку.
4. **Второй слой не рендерится вовсе, если тёмной версии нет.** Магазин без пар отдаёт сегодняшний
   HTML байт в байт.
5. **Прогрев — в переключателе, а не по поверхностям.** Перед записью `data-mode` переключатель
   переводит неактивные слои в `loading="eager"`, ждёт их готовности с ограничением сверху и только
   потом меняет режим. Ожидание ограничено: режим переключается всегда.

Общий компонент: `apps/storefront/src/modules/common/components/mode-image`. Ни одна поверхность не
пишет правило подмены сама — иначе через месяц их будет три разных.

## 4. Формат набора данных

Ось режима в файлах профиля (`apps/backend/src/migration-scripts/data/profiles/<id>/`), чтобы
сгенерированная пара могла лечь в набор. Генерация — трек `feat/abstract-datasets`, здесь только
формат.

- `media/manifest.json` (`upready.store-media-manifest/v0`): у записи появляется необязательное
  `mode` со значениями `light` | `dark`. Отсутствует — кадр годится в оба режима. Пара опознаётся по
  совпадению `role` и `productHandle`/`categoryHandle` при разных `mode`.
- `profile.json` (`upready.store-profile/v0`): рядом с `home.hero.image` — `imageDark`, рядом с
  `home.categoryTiles[].image` — `imageDark`. Оба необязательны, оба `mediaRef`.
- `catalog/products.json` (`upready.store-catalog-products/v0`): у товара — необязательный
  `imageDark` (`mediaRef`), тёмный близнец ГЛАВНОГО кадра (`images[0]`).

Валидатор `apps/backend/scripts/validate-store-profile.mjs` проверяет тёмные ссылки теми же
правилами, что светлые: файл существует, sha256 совпадает, запись в манифесте `accepted`.

## 5. Границы

- Пара работает для ГЛАВНОГО изображения товара — карточка и первый кадр галереи. Остальные кадры
  галереи одинаковы в обоих режимах: заказ Ивана — «по 2 изображения для каждого товара», то есть
  одна пара на товар, а не удвоение галереи.
- Тёмная версия товара НЕ кладётся в `product.images[]`: витрина показывает каждый элемент этого
  списка отдельным слайдом, и дубль стал бы лишним слайдом в светлом режиме.
- Ось режима не трогает `data-theme`: пресет темы и режим — разные оси, пара живёт у данных и
  одинаково работает во всех семи пресетах.
